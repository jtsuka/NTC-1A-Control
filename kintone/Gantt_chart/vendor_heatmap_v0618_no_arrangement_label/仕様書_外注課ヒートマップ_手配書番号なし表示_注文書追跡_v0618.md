# 外注課ヒートマップ改修仕様書

## 1. 改修概要

- 対象：外注課 外注先負荷ヒートマップ / 日程リスク可視化
- 版：Ver0.6.1.8
- 依頼元：宮田課長
- 対象アプリ：App292（TEST）で先行確認後、App272（本番）へ反映予定

## 2. 改修目的

外注課では、営業マンからの手配を起因としない発注があり、その場合は手配書番号が存在しない。
従来表示では手配書番号が空欄の場合、kintoneのレコード番号（例：`#4`）が代替表示されていたため、外注課オペレーターから見て案件の意味が分かりにくかった。

一方、手配書番号がない案件でも注文書番号（内部フィールド：注文伝票番号）を保持できるため、注文書番号を追跡キーとして利用できる。

## 3. 表示仕様

### 3.1 手配書番号がある場合

- 従来どおり手配書番号を表示する。
- 注文書番号も併記する。

例：

```text
T268059011
注文書 2608120819
```

### 3.2 手配書番号がない場合

- kintoneレコード番号（`#4`等）は表示しない。
- `手配書番号なし` と明示する。
- 注文書番号を併記し、オペレーターが注文書から追跡できるようにする。

例：

```text
手配書番号なし
注文書 999999999
```

## 4. 対象表示箇所

- 日程リスク一覧の「手配書番号」欄
- 案件詳細／予定表の左固定列「手配書番号 / 注文書番号」
- 注文書番号表示はVer0.6.1.7で追加した仕様を継続する。

## 5. 使用フィールド

| 用途 | kintoneフィールド | 備考 |
|---|---|---|
| 手配書番号 | `K手配書番号` / `ルックアップ` | 既存ロジックに従い優先取得 |
| 注文書番号 | `数値_44` | kintone表示名：注文伝票番号 |
| レコードID | `$id` | 内部リンク用のみ。画面の代替表示には使用しない |

## 6. 判定ロジック

```text
手配書番号あり
  → 手配書番号を表示

手配書番号なし
  → 「手配書番号なし」と表示

注文書番号あり
  → 「注文書 <番号>」を併記

注文書番号なし
  → 「注文書 —」を表示
```

## 7. 非変更範囲

今回の改修では以下は変更しない。

- 日程リスク判定
- 外注先別負荷計算
- K加工着手日 / K完成検査日の扱い
- Manual / Batch / Auto の日程種別処理
- 入荷日登録・取消処理
- 外注先クイックフィルタ

## 8. TEST確認結果／確認項目

App292で、手配書番号を空欄としたレコードの新規登録・再取得・ヒートマップ表示が可能であることを確認済み。

Ver0.6.1.8適用後は次を確認する。

1. 手配書番号あり案件が従来どおり番号表示される。
2. 手配書番号なし案件が `#<レコード番号>` ではなく `手配書番号なし` と表示される。
3. 両ケースで注文書番号が表示される。
4. レコードリンクが従来どおり開く。
5. 日程リスク、負荷ヒートマップ、案件詳細、入荷操作に回帰不具合がない。
