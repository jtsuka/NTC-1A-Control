# 外注負荷ヒートマップ 下段ガント表示レイアウト変更仕様書
## Ver0.6.0.3 実装版 / Claudeクロスレビュー提出用
### 2026-09-08

---

## 1. 目的

本改修は、App272「外注課発注データ-TEST」の独自ヒートマップ画面における
**下段の案件詳細ガントを、現在利用中の標準ガントプラグインに近い見た目へ寄せ、会議・テレビ表示でも読みやすくする**
ことを目的とする。

今回の改修対象は主として見た目・レイアウトであり、
既存のヒートマップ集計ロジック、日付判定、Manual保護、kintone標準絞り込み連動等の機能ロジックは変更しない。

---

## 2. 背景

### 2.1 標準ガントの見た目を好む利用者が一定数いる

現在利用中の無料ガントチャートプラグインは表示速度に難点がある一方、
従来から利用しているため、以下の点を見やすいと感じる利用者が一定数いる。

- 左側に案件識別情報がまとまっている
- 右側に日付軸とガントが並ぶ
- 行単位で「どの案件か」を追いやすい
- kintone標準の絞り込みと組み合わせて使える

独自ヒートマップの下段ガントは機能面では詳細だが、
情報量を詰め込んでいるため、会議室テレビ等では文字が小さく見えるという指摘が想定される。

---

### 2.2 業務上、手配書番号は最重要識別情報

社内では、営業担当者が最初に入力する伝票番号＝手配書番号を基準に業務が進む。

したがって、案件一覧・ガント表示においても
**手配書番号を最左列の主要識別情報として常時表示する**
ことが必要である。

---

### 2.3 標準絞り込み連動との相性

Ver0.5.9.1で、
kintone標準一覧の絞り込み条件が
ヒートマップ・リスク一覧・下段ガントへ連動するようになった。

このため今後は、

- 指示先名で絞る
- 手配担当者で絞る
- 手配書番号で絞る

といった標準kintone操作を行ったうえで、
下段ガントを案件一覧として確認する使い方が増えると想定する。

この用途では、
左側に案件識別情報が明確に並ぶ標準ガント風レイアウトが適している。

---

## 3. 基本方針

下段ガントを以下の4ブロック構成とする。

```text
手配書番号 ｜ 指示先名 ｜ 手配担当者 ｜ ガントチャート
```

画面イメージ：

```text
手配書番号   指示先名          手配担当者   ｜ 9/8  9/9  9/10  9/11 ...
T269045260   ㈱山和（八尾）     宮田         ｜   ━━━━━━━●◆
T268085070   ㈲山口製作所       井田         ｜      ━━━━━●◆
L267000170   ○○製作所           宮田         ｜ ━━━━━━━━━●◆
```

左3列は案件識別用、
右側を現在の横スクロール可能な日付ガント領域とする。

---

## 4. 表示項目

### 4.1 左固定列

左側に以下3列を固定表示する。

| 列 | 表示内容 | 役割 |
|---|---|---|
| 1 | 手配書番号 | 案件の最重要識別キー |
| 2 | 指示先名 | 加工先・外注先の識別 |
| 3 | 手配担当者 | 社内担当者の識別 |

### 4.2 手配書番号

今後の正式表示キーは `K手配書番号` を使用する。

ただし、`K手配書番号` は新設フィールドであり、
既存レコードには未同期・空欄が残る可能性があるため、
**Ver0.6.0.1でフォールバック表示を必須実装とする。**

表示優先順位：

```text
1. K手配書番号
2. 旧Lookup手配書番号
3. #レコード番号
```

概念例：

```javascript
displayOrderNo =
  K手配書番号 ||
  旧Lookup手配書番号 ||
  ('#' + recordId);
```

これにより、
新旧フィールド移行途中でも手配書番号列が空欄にならないようにする。

旧Lookupは表示フォールバック用途で参照するだけであり、
Ver0.6.0.1のレイアウト変更処理からLookup値を更新することはしない。

### 4.3 指示先名

現行Ver0.5.9.1のnormalize処理をそのまま流用する。

表示優先順位：

```text
VENDOR_DD
↓ 空欄なら
VENDOR_TEXT
```

新しい判定ロジックは追加しない。

### 4.4 手配担当者

現行Ver0.5.9.1のnormalize処理をそのまま流用する。

表示優先順位：

```text
STAFF_DD
↓ 空欄なら
STAFF_TEXT
```

新しい判定ロジックは追加しない。

## 5. 固定列仕様

### 5.1 固定表示

左3列は横スクロールしても常時表示する。

右側ガントの日付軸のみ横スクロールする。

目的：

- 手配書番号を見失わない
- どの行のガントか常に判断できる
- テレビ表示でも案件名とバーの対応を追いやすくする

---

### 5.2 推奨列幅

初期案：

| 列 | 標準 | 大 | 特大 |
|---|---:|---:|---:|
| 手配書番号 | 120px | 140px | 160px |
| 指示先名 | 170px | 200px | 230px |
| 手配担当者 | 100px | 120px | 140px |

実機表示を見て微調整する。

固定幅を基本とし、
長い文字列は省略表示＋ツールチップで全文確認できる方式を推奨する。


### 5.3 sticky列幅・leftオフセットの管理

左3列のsticky `left` 値をpx直書きで個別管理しない。

標準 / 大 / 特大で列幅が変化するため、
CSS変数で列幅を定義し、各列のleft値を計算する方式を採用する。

概念例：

```css
--eh-col-order-w: 120px;
--eh-col-vendor-w: 170px;
--eh-col-staff-w: 100px;

.eh-col-order {
  left: 0;
}

.eh-col-vendor {
  left: var(--eh-col-order-w);
}

.eh-col-staff {
  left: calc(
    var(--eh-col-order-w) +
    var(--eh-col-vendor-w)
  );
}
```

サイズ切替時はCSS変数値のみを変更し、
stickyオフセットの整合を自動的に保つ。

## 6. 文字サイズ

現在の「標準 / 大 / 特大」表示切替を維持する。

ただし下段ガントについては、
特に「大」「特大」で左3列の文字を現状より見やすくする。

推奨：

| サイズ | 本文文字 |
|---|---:|
| 標準 | 12～13px |
| 大 | 14～15px |
| 特大 | 16～18px |

特大は会議室テレビでの閲覧を意識する。

---

## 7. 行高

現在より少し余裕を持たせる。

推奨：

| サイズ | 行高 |
|---|---:|
| 標準 | 30～32px |
| 大 | 34～36px |
| 特大 | 38～42px |

目的：

- 手配書番号を読みやすくする
- ガントバーとマーカーを見分けやすくする
- Manual行の強調表示を見やすくする


### 7.1 ガント要素の縦位置

現行CSSには、ひげ・ワークバー・マーカー等の `top:` 固定px値が
標準 / 大 / 特大ごとに複数箇所ハードコードされている。

行高変更時の位置ズレ・修正漏れを防ぐため、
実装時には対象箇所を事前に洗い出す。

可能な要素については、

```css
top: 50%;
transform: translateY(-50%);
```

等の**行高に依存しにくい中央揃え方式**への変更を優先検討する。

ただし、マーカー同士の意図的な上下分離など、
現行デザイン上top固定が必要なものは無理に一本化しない。

実装前に
「行高に依存するtop固定値一覧」
を確認し、変更対象を明確にする。

---

## 8. 手配書番号の強調

手配書番号は最左列で太字表示する。

例：

```text
T269045260
```

レコード詳細へのリンク機能は維持する。

現在レコード番号等をクリックして詳細画面へ遷移している場合は、
手配書番号自体をリンク化することも候補とする。

ただし、既存リンク挙動を壊さないことを優先する。

## 10. 商品名の扱い

商品名は左固定列には追加しない。

理由：

- 左列が広がり過ぎるとガント領域が狭くなる
- 今回の主目的は手配書番号・指示先・担当者を明確にすること
- 商品名は現在どおりガントバー内で短く表示できる

必要に応じてマウスオーバーで全文表示する。

---

## 11. Manual表示

Ver0.5.8で実装したManual可視化は維持する。

Manual行では：

- `M` バッジ
- 太枠
- 淡い背景

を維持する。

### 11.1 左3列すべてへのManual表示適用

現行では `.eh-manual-row .eh-gantt-info` の単一情報ブロックに対して
背景・太枠を適用している。

Ver0.6.0.1では左情報欄を3列へ分割するため、
**Manual背景・太枠は「手配書番号 / 指示先名 / 手配担当者」の3列すべてに必ず適用する。**

1列だけにManual背景が残り、他2列が通常色になる状態は不可とする。

### 11.2 Mバッジ位置

`M` バッジは手配書番号列へ配置する。

例：

```text
[M] T269045260
```

既存の `.eh-manual-badge` クラスを原則流用し、
見た目の意味は変更しない。

赤は引き続き日付矛盾・要注意専用とし、
Manual色とは意味を混同しない。

## 16. 日付矛盾・要注意

- 手配日 / 加工着手日 / 完成検査日 / 納期 のいずれかが未設定

### 18.1 PC前提

### 18.2 狭い画面

## 19. 性能

今回の変更は主としてHTML/CSSレイアウト変更であり、
レコード取得件数・ヒートマップ集計・日付計算は増えない。

したがって、
API負荷は原則Ver0.5.9.1と同等とする。

注意点：

- 左3列のsticky要素が増える
- DOM要素数が若干増える
- 各行の固定列セル描画が追加される

ただし、
1日ごとに大量DOMを追加する方式には変更しないため、
大きな性能悪化は避ける。

Canvas / SVGへの全面変更は行わない。

---

## 20. 既存標準ガントとの関係

本改修の目的は、
既存無料ガントを即時廃止することではない。

当面は：

```text
標準ガント
  → 従来利用者向け

独自ヒートマップ＋下段ガント
  → 負荷可視化＋案件確認＋絞り込み
```

として併存する。

独自画面の使い勝手が十分評価され、
標準ガント利用者が減った段階で、
旧Lookup依存やプラグイン廃止を将来検討する。

## 28. Ver0.6.0.3 実装内容

Ver0.6.0.1で確定した設計を以下の通り実装した。

### 28.1 JS

- `CONFIG.fields.key` を `K手配書番号` へ変更
- `CONFIG.fields.keyFallback = 'ルックアップ'` を追加
- normalize時に `key` / `keyFallback` を保持
- 表示手配書番号を
  `K手配書番号 → 旧Lookup → #レコード番号`
  の順で決定
- 下段1行を
  `手配書番号 / 指示先名 / 手配担当者 / ガント`
  の4ブロックへ変更
- Mバッジを手配書番号列へ配置
- 商品名は左列から外し、既存どおり加工期間バー内表示
- 日付列・inline riskは手配書番号セル内の補助情報として維持
- 指示先・担当者はnormalize済み値を流用するため、
  `VENDOR_DD→VENDOR_TEXT`,
  `STAFF_DD→STAFF_TEXT`
  の既存フォールバックを維持

### 28.2 CSS

- 3固定列をsticky化
- 標準/大/特大の列幅をCSS変数化
- sticky left値をCSS変数のcalcで算出
- Manual背景を3固定列すべてへ再適用
- Mバッジを手配書番号セル内で維持
- workbarとwhiskerを `top:50%` 基準へ変更し、
  行高依存の固定top値を最終overrideで無効化
- マーカーは既存のtop:50%系実装を維持
- 既存のヒートマップ・リスク・絞り込みロジックは変更なし

### 28.3 実装時の意図的な判断

行高そのものはVer0.5.9.1の標準/大/特大の既存値を維持した。
理由は、現行のバー高さ・日付補助情報・Manual表示との視認性が既に実機確認済みであり、
今回の主目的を「3固定列化と文字の読みやすさ」に限定して回帰リスクを抑えるため。

## 29. Ver0.6.0.3 Claudeクロスレビュー反映

### 29.1 手配書番号フォールバックの共通化

Ver0.6.0.2では下段ガントのみ3段フォールバックが実装され、
上段「要注意／リスク一覧」は旧2段フォールバックのままだった。

Ver0.6.0.3ではnormalize時に `displayKey` を生成する。

```text
displayKey =
  K手配書番号
  → 旧Lookup
  → #レコード番号
```

上段リスク一覧・下段ガントとも `displayKey` を使用し、
表示の不一致を解消する。

### 29.2 旧2列grid定義の削除

旧 `--eh-left-width` ベースの2列 `grid-template-columns` 定義を削除した。

さらに、未使用となった `--eh-left-width` のサイズ別宣言も削除した。

Ver0.6.0.3では以下の4列定義のみを正式なgrid定義とする。

```text
手配書番号
指示先名
手配担当者
ガント
```

4列定義側へ以下も集約した。

- `display:grid`
- `gap:0`
- `width:max-content`
- `min-width:100%`

これによりCSSの並び順だけで新旧レイアウトが切り替わる状態を解消する。

### 29.3 変更しない機能

- kintone標準絞り込み連動
- Manual表示
- 日付矛盾・要注意判定
- ヒートマップ集計
- 30/60/90日切替
- 標準/大/特大
- ガントバー・マーカーの意味
