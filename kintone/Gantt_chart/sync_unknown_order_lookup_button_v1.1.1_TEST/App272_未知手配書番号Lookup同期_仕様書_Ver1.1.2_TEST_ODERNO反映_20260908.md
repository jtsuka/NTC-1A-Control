# App272 未知手配書番号 Lookup同期ボタン 仕様書
## Ver1.1.2 TEST / フィールドコード ODERNO 正式反映 / 2026-09-08

## 1. 修正理由

App272の画面上の表示名は「K手配書番号」だが、
実際のkintoneフィールドコードは `ODERNO` であることを実機設定画面で確認した。

これまでのVer1.1.1 TESTでは、

```javascript
key: 'K手配書番号'
```

としていたため、REST APIで

`GAIA_IQ11: 指定されたフィールド（K手配書番号）が見つかりません。`

となる。

Ver1.1.2 TESTでは、App272正式キーのフィールドコードを
`ODERNO` に修正する。

---

## 2. App272正式キー

- 表示名：K手配書番号
- フィールドコード：`ODERNO`
- 型：文字列（1行）

CSV取込・同期ボタン・将来のPowerShell/REST APIでは、
画面上の表示名ではなくフィールドコード `ODERNO` を使用する。

---

## 4. TEST安全ガード

Ver1.1.1で確認済みの安全機構はそのまま維持する。

- App270未登録想定：
  `TEST260908001`
- App272旧Lookup更新対象キー：
  `TEST260908001`
- App272旧Lookup更新対象件数：
  `1`

想定と実際が一致しない場合は書込み前に停止する。

---

## 5. App270側の前提

App270の手配書番号 `文字列__1行_` は

- 必須
- 値の重複禁止 ON

であることを実機で確認済み。

今回TESTではApp270既存レコードの納期更新は行わない。

---

## 6. 処理フロー

```text
App272 CSV取込
↓
CSV手配書番号 → ODERNO（表示名：K手配書番号）
↓
旧LookupにはCSVから直接入れない
↓
同期ボタン
↓
App272.ODERNO と App270.文字列__1行_ を比較
↓
未知番号だけApp270へ追加
↓
App270再取得で存在確認
↓
App272旧Lookup「ルックアップ」へ同じ番号を反映
```

## 8. Ver1.1.1からのコード変更点

変更はApp272正式キーのフィールドコードのみ。

旧：

```javascript
fields272: {
  id: '$id',
  key: 'K手配書番号',
  oldLookup: 'ルックアップ',
  due: '日付_1'
}
```

新：

```javascript
fields272: {
  id: '$id',
  key: 'ODERNO',
  oldLookup: 'ルックアップ',
  due: '日付_1'
}
```

安全ガード、App270追加、再確認、Lookup更新、K日程保護には変更なし。
