## 1. 目的

現行の「全外注先に同一の暫定日程ルールを一括適用する方式」から、

**外注先ごとに異なる基準日数を設定し、選択した外注先だけに暫定日程を反映できる方式**

へ変更する。

あわせて、

- その案件を暫定日程の対象にするか
- 現在の日程が自動設定か、人が意図的に変更した日程か
- 人が変更した日程を次回の自動処理で上書きしないこと
- 自動設定した日程だけを安全に解除できること

をレコード単位で管理する。

---

## 2. 追加フィールドと初期値

本仕様では、kintoneフォーム側で以下の初期値が設定済みであることを前提とする。

- `K暫定設定`：初期値 `OFF`
- `K日程種別`：初期値 `Auto`

したがって、**Rev.3導入後に新規追加されるレコードは、通常必ず
`K暫定設定 = OFF` かつ `K日程種別 = Auto` の状態で作成される。**

この初期値を、新規レコードに対する正式な基準状態とする。

### 2.1 暫定設定

- フィールド名：`暫定設定`
- フィールドコード：`K暫定設定`
- 種類：ドロップダウン
- 選択肢：
  - `ON`
  - `OFF`
- 初期値：`OFF`

### 新規レコード時の扱い

kintoneフォームの初期値により、新規追加時は原則として必ず `OFF` となる。

そのため、新規レコードが追加された直後に自動日程が勝手に反映されることはない。
オペレーターまたは運用側が明示的に `ON` とした案件だけが暫定日程設定の対象になる。

### 役割

そのレコードを暫定日程の自動設定対象にするかを表す。

- `ON`：暫定日程設定の対象
- `OFF`：自動処理では変更しない

---

### 2.2 日程種別

- フィールド名：`日程種別`
- フィールドコード：`K日程種別`
- 種類：ドロップダウン
- 選択肢：
  - `Auto`
  - `Manual`
- 初期値：`Auto`

### 新規レコード時の扱い

kintoneフォームの初期値により、新規追加時は原則として必ず `Auto` となる。

その後、オペレーターが標準編集画面で
`K加工着手日` または `K完成検査日` を実際に変更して保存した場合にだけ、
本スクリプトが自動で `Manual` へ切り替える。

### 役割

現在の `K加工着手日` / `K完成検査日` が、
自動設定によるものか、人が意図的に変更したものかを表す。

- `Auto`：自動計算された日程。再計算・基準日程への復元対象にできる
- `Manual`：人が意図的に変更した日程。自動処理では保護する

---

## 2.3 既存レコードの空欄値の扱い（Rev.3.5追加）

フィールド追加前から存在する既存レコードでは、フォーム初期値が遡及しないため、

- `K暫定設定` が空欄
- `K日程種別` が空欄

のレコードが存在し得る。

Rev.3.5では、これをエラーやManual扱いにはせず、フォーム初期値相当として扱う。

- `K暫定設定` 空欄 → `OFF` 相当
- `K日程種別` 空欄 → `Auto` 相当

そして暫定ON/OFF処理で対象レコードを実際に更新した際に、

- 暫定ON実行 → `K暫定設定 = ON`、`K日程種別 = Auto`
- 暫定OFF実行 → `K暫定設定 = OFF`、`K日程種別 = Auto`

へ正規化する。

このため、既存データの空欄は運用の中で徐々に解消され、
新規レコードはフォーム初期値により最初から `OFF / Auto` となる。

## 3. 画面上部UI

### 現行

`検 [3]　着 [5]　暫定 ON/OFF`

### Rev.3

`外注先 [▼]　検 [n]　着 [n]　[暫定ON] [暫定OFF]`

### 3.1 外注先プルダウン

- App272 の `VENDOR_DD` から候補を取得
- 重複を除いて一覧化
- 選択した外注先だけを処理対象とする
- 外注先未選択時はON/OFFとも実行不可

### 3.2 検

完成検査日を「納期の何日前」とするかを指定する。

例：

`検 5`  
→ `K完成検査日 = 納期の5日前`

### 3.3 着

加工着手日を「完成検査日の何日前」とするかを指定する。

例：

`着 7`  
→ `K加工着手日 = K完成検査日の7日前`

### 3.4 暫定ON

選択した外注先について、
条件を満たすレコードだけに暫定日程を反映する。

対象条件：

- `VENDOR_DD = 選択外注先`
- `K暫定設定 = ON`
- `K日程種別 = Auto`

### 3.5 暫定OFF

選択した外注先について、
**Auto日程を基準日程へ戻す。**

対象条件：

- `VENDOR_DD = 選択外注先`
- `K日程種別 = Auto` または空欄（空欄はAuto相当）

処理内容：

- `K加工着手日 = 手配日`
- `K完成検査日 = 納期`
- `K暫定設定 = OFF`
- `K日程種別 = Auto`

`K日程種別 = Manual` のレコードは絶対に変更しない。

旧v2.1のような全レコード一括復元ではなく、
**選択外注先＋Auto限定で基準日程へ戻す安全な復元処理**とする。

### 3.6 ボタン状態

- ON/OFFボタンはグローバル状態を保持しない
- 実行中のみ `処理中...` 表示
- 実行中は対象ボタンを無効化
- 二重実行を防止
- 完了後は通常表示へ戻す

## 4. 暫定日程の計算ルール

現行 v2.1 の計算方式を継承する。

### 4.1 完成検査日

`K完成検査日 = 納期 - 検の日数`

土日祝の場合は、前の稼働日へ戻す。

### 4.2 加工着手日

`K加工着手日 = K完成検査日 - 着の日数`

土日祝の場合は、次の稼働日へ送る。

### 4.3 日付チェック

以下の場合はON反映しない。

- 納期が未設定
- 日付形式が不正
- 加工着手日 > 完成検査日
- 完成検査日 > 納期
- 加工着手日 < 手配日（短納期候補）

---

## 5. 暫定ONの対象条件

暫定日程を自動設定するのは、以下を**すべて満たすレコードのみ**とする。

1. `VENDOR_DD = 画面で選択した外注先`
2. `K日程種別 = Auto` または空欄（空欄はAuto相当）
3. 納期が存在する
4. 日付計算結果に矛盾がない

※ `K暫定設定` の現在値はONの前提条件にしない。
暫定ONボタン自体が `K暫定設定 = ON` に切り替える操作である。

### ON時に更新しない条件

- 外注先が一致しない
- `K暫定設定 = OFF`
- `K日程種別 = Manual`
- 納期未設定
- 短納期候補
- 日付関係異常

---

## 6. 暫定OFFの対象条件

暫定OFFは、選択した外注先のうち
**`K日程種別 = Auto` のレコードだけ**を対象とする。

### OFF時の処理

- `K加工着手日 = 手配日`
- `K完成検査日 = 納期`

手配日または納期が未設定の場合は更新せず、要確認として集計する。

### OFF時に変更しない条件

- 外注先が一致しない
- `K日程種別 = Manual`
- 手配日または納期が未設定

Manual案件は、K日付がどのような値であっても自動復元しない。

---

## 7. Auto / Manual の安全ルール

### 7.1 自動反映時

暫定ONで自動設定した場合：

- `K加工着手日` を更新
- `K完成検査日` を更新
- `K暫定設定 = ON`
- `K日程種別 = Auto`

既存レコードで `K暫定設定` または `K日程種別` が空欄の場合も、
更新時に正式値へ正規化する。

REST APIによる一括更新では、
標準レコード編集画面の編集・保存イベントを通さないため、
Manual自動切替は発生させない。

---

### 7.2 手動変更時のManual自動設定【Rev.3重要変更】

オペレーターに `K日程種別` の変更を手作業で要求しない。

**標準レコード編集画面で、K日付が実際に変更された場合に
JavaScriptで自動的に `K日程種別 = Manual` に設定し、
同じ保存処理で一緒に保存する。**

対象フィールド：

- `K加工着手日`
- `K完成検査日`

### 判定方法

1. `app.record.edit.show` で編集開始時のK日付を保持
2. `app.record.edit.submit` で保存直前のK日付と比較
3. どちらか一方でも値が変わっていれば、
   `K日程種別 = Manual`
4. それ以外のフィールドだけを変更した場合は、
   `K日程種別` を変更しない

概念コード：

```javascript
let originalStart = '';
let originalInspection = '';

kintone.events.on('app.record.edit.show', function (event) {
  originalStart = event.record['K加工着手日'].value || '';
  originalInspection = event.record['K完成検査日'].value || '';
  return event;
});

kintone.events.on('app.record.edit.submit', function (event) {
  const currentStart =
    event.record['K加工着手日'].value || '';

  const currentInspection =
    event.record['K完成検査日'].value || '';

  if (
    currentStart !== originalStart ||
    currentInspection !== originalInspection
  ) {
    event.record['K日程種別'].value = 'Manual';
  }

  return event;
});
```

### 目的

オペレーターがManualフラグを立て忘れても、
**K日付を人が変更した事実そのものを検知して自動保護する。**

これをManual保護の正式な仕組みとする。

---

### 7.3 Manualの保護

`K日程種別 = Manual` のレコードは、

- 暫定ONによる再計算
- 暫定OFFによる基準日程（手配日／納期）への復元

の**どちらからも保護する。**

## 8. 外注先ごとの設定値保存

### 8.1 TEST／プレビュー版

外注先ごとの `検 / 着` は `localStorage` に保存する。

### 8.2 保存方式

外注先ごとに個別キーを乱立させず、
**1つのstorageKeyにJSONオブジェクトとしてまとめて保存する。**

保存キー例：

`schedulePreview.vendorRules`

保存イメージ：

```json
{
  "㈱山和（八尾）": {
    "inspectionDaysBeforeDue": 5,
    "startDaysBeforeInspection": 7
  },
  "㈲山口製作所": {
    "inspectionDaysBeforeDue": 15,
    "startDaysBeforeInspection": 10
  }
}
```

### 8.3 外注先選択時

- 保存済み設定があれば、その会社の `検 / 着` を入力欄へ復元
- 保存値がなければ既定値を使用
- 外注先名そのものはJSON内のプロパティキーとして扱う

### 8.4 正式運用候補

将来は別途「外注先日程ルールマスタ」をkintone上に持ち、
ブラウザ依存をなくすことを検討する。

## 15. 現行未使用関数の扱い

**原則として `isAutoProvisionalRecord()` は削除候補とする。**

推測ロジックと明示フィールドを併存させない。

## 16. 現行 v2.1 からの主な変更点

- `K暫定設定` 空欄 → OFF相当

### 変更3：旧「全件」復元処理を廃止

旧v2.1の全レコード一括復元は廃止する。

### 変更4：外注先＋Auto限定の基準日程復元を追加

選択外注先＋`K日程種別 = Auto` のレコードだけ、

- `K加工着手日 = 手配日`

へ戻す。

### 変更5：Manual自動検知を正式実装

標準編集画面でK日付を変更して保存した場合、
自動で `K日程種別 = Manual` にする。

### 変更6：ManualをON/OFF双方から保護

Manual案件は再計算も基準日程への復元も行わない。

### 変更7：確認メッセージを正常化

現行の「空欄だけ反映」と「既存値上書き」の矛盾を解消する。

### 変更8：外注先ごとの検／着保存

単一localStorageキー配下のJSONとして保存する。

### 変更9：集計処理を新設

各レコードを条件別に分類し、
確認・結果表示へ利用する。

## 18. Rev.3導入時の既存データ初期化

### 18.1 新規レコード

Rev.3導入後に新しく追加されるレコードについては、
kintoneフォームの初期値により以下の状態で作成される。

- `K暫定設定 = OFF`
- `K日程種別 = Auto`

したがって、**新規レコードについては初期化処理を別途行う必要はない。**

### 18.2 既存レコード

フィールド追加前から存在している既存レコードについては、
kintoneフォームの初期値が過去データへ自動的に遡及しないため、
`K暫定設定` または `K日程種別` が空欄のレコードが存在する可能性がある。

Rev.3.5では、既存空欄をON/OFF操作時に初期値相当として吸収し正規化するため、
一括初期化は必須ではない。必要に応じて事前一括初期化を行ってもよい。

TESTアプリでは、既存データの扱いを確認した上で以下を基準とする。

- `K暫定設定` 空欄 → `OFF`
- `K日程種別` 空欄 → `Auto`

これにより、既存レコードも新規レコードと同じ初期状態へ揃える。

※ 本番移行時に既存K日付へ手作業による修正が含まれている場合は、
`K日程種別` を一律Autoにする前に既存データを確認すること。

## 19. Manual → Auto の暫定運用

専用のAuto復帰操作は今回実装しない。

Manual案件をAutoへ戻す必要がある場合は、

1. K日付は変更しない
2. `K日程種別` だけを `Manual` → `Auto` に変更
3. 保存する

という運用とする。

同じ保存操作で `K加工着手日` または `K完成検査日` も変更した場合は、
保存前比較によるManual自動検知が働き、再び `Manual` になる。

## 20. データ取込方法と今後の自動化方針

### 20.1 現時点の運用

現時点では、外注課発注データへの取込は
**手動でCSVデータを取り込む暫定運用**とする。

手動CSV取込（「レコードの更新と追加」、更新キー：発注番号）は
**実際に動作することを確認済み**である。

したがって、暫定運用ルート自体は成立しており、
外注先別暫定日程機能のテストはこのデータ取込方法を前提に進めてよい。

### 20.2 暫定期間中の方針

1. 基幹側または元データからCSVを作成
2. オペレーターがkintoneへCSVを手動取込
   （「レコードの更新と追加」、更新キー：発注番号）
3. kintone上で追加・更新されたデータを使用
4. 本スクリプトで外注先別の暫定日程を設定

この手動CSV取込は正式運用ではなく暫定処置だが、
現時点で機能している運用として扱う。

### 20.3 手配書番号まわりの追加・更新制約の再確認

RK-10＋PowerShell＋REST APIによる新規追加・更新の自動化を検討する過程で、
**手配書番号まわりに何らかの追加・更新制約が残っている可能性がある**ことが分かった。

ただし、フィールドコード名が `ルックアップ` であることをもって
LOOKUP型が原因と決めつけることはできない。
過去の確認では、当該フィールドの型は `SINGLE_LINE_TEXT` であった。

そのため現時点では、原因を以下のいずれかに絞り込むことを次の課題とする。

- フィールド型（LOOKUP型に変更されていないか）
- 必須設定
- 値の重複禁止（unique）設定
- 他アプリ・他フィールドとの参照関係

原因が特定でき次第、対応方針を確定する。

### 20.4 正式運用時の予定

手配書番号まわりの制約を解消した後は、
RK-10からPowerShellスクリプトを起動し、
kintone REST APIを使用してデータの取込・追加・更新を行う方式へ移行する予定とする。

正式運用イメージ：

```text
RK-10
  ↓
PowerShell起動
  ↓
元データ取得・整形
  ↓
kintone REST API
  ↓
新規追加 / 既存更新
  ↓
K日程項目は保護ルールに従って更新
```

この際、

- 新規追加時はフォーム初期値として `K暫定設定 = OFF`、`K日程種別 = Auto`
- 既存レコード更新時は `K日程種別 = Manual` のK日付を上書きしない
- 外注先別暫定日程は本仕様のON/OFFロジックに従う

という安全条件を維持する。

### 20.5 自動化移行の位置づけ

今回のRev.3.5は、
**手動CSV取込（動作確認済み）を前提に、外注先別日程制御を先に成立させる段階**とする。

並行して手配書番号まわりの制約原因を特定し、
次段階でRK-10＋PowerShell＋APIによる正式自動取込／更新へ移行する。
