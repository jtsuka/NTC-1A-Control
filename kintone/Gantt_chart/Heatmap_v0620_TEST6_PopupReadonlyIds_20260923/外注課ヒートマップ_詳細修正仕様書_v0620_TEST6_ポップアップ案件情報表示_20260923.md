# 外注課ヒートマップ Ver0.6.2.0-TEST6
## 日程編集ポップアップ 案件識別情報（表示のみ）追加 詳細修正仕様書
### 2026-09-23

## 1. 目的

日程編集ポップアップでは、ヘッダーに

```text
外注先 / 手配書番号
```

を表示しているが、編集項目が増えたため、
「今どの案件を修正しているか」を本文内でも明確に確認できるようにする。

TEST6では、ポップアップ本文の最上部に
**案件情報（表示のみ）**を追加する。

表示項目:

```text
手配書番号
注文書番号
```

いずれも表示専用とし、編集・保存・PUT対象にはしない。

---

## 2. 表示仕様

ポップアップ本文の先頭に以下を表示する。

```text
案件情報（表示のみ）

手配書番号   T259011080
注文書番号   2509036641
```

その下に従来の編集項目を表示する。

```text
K加工着手日
K完成検査日
K暫定設定
手配担当者名
外注入荷日
受入れ日
```

---

## 3. 手配書番号

取得元は、ポップアップを開いた時点で再GETした最新レコード。

優先順位:

```text
ODERNO
↓
旧fallbackフィールド
↓
手配書番号なし
```

表示値が存在しない場合は必ず

```text
手配書番号なし
```

と表示する。

入力欄にはしない。

---

## 4. 注文書番号

取得元:

```text
CONFIG.fields.orderSlipNo
= 数値_44
```

画面上の名称は従来どおり

```text
注文書番号
```

とする。

値あり:

```text
2509036641
```

値なし:

```text
—
```

と表示する。

入力欄にはしない。

---

## 5. 最新値の扱い

下段ガントや日程リスク表に表示されているキャッシュ値ではなく、
`openScheduleEditPopup()`が実行する最新1件GETの`raw`から取得する。

これにより、一覧表示後に他操作で番号が変化した場合でも、
ポップアップでは開いた時点の最新値を表示する。

---

## 6. 保存処理への非影響

手配書番号・注文書番号は、以下のどれにも追加しない。

```text
activeEdit.initial の編集比較対象
collectActiveEditValues()
activeEditIsDirty()
validateActiveEdit()
payloadRecord
PUT
```

従って、

- 表示しただけでdirtyにならない
- 保存ボタンを押しても番号はPUTされない
- CSV正本項目をポップアップから変更できない

ことを保証する。

本文先頭に薄い背景の情報カードとして表示する。

CSSクラス:


「表示のみ」であることを明示する。

## 9. 追加受入試験

### E34 案件情報表示

```text
- 手配書番号あり → 正しい番号を表示
- 手配書番号なし → 「手配書番号なし」と表示
- 注文書番号あり → 正しい番号を表示
- 注文書番号なし → 「—」表示
- 下段ガント/日程リスクのどの起動経路でも同じ表示になる
```

### E35 表示専用保証

```text
- 手配書番号/注文書番号に入力UIがない
- 表示情報だけではdirtyにならない
- 保存payloadにODERNO/注文書番号が含まれない
- K日程等だけ変更した時も番号系フィールドはPUTされない
- 「その他の項目を標準画面で編集」は従来どおり動作する
```
