# 外注課負荷ヒートマップ Ver0.6.1.6 詳細仕様設計書

**機能名:** 外注先クイックフィルタ（複数選択対応）\
**作成日:** 2026-09-14\
**母体:** Ver0.6.1.5 `vendor_heatmap_v0615_today_marker.js / .css`\
**位置づけ:** Ver0.6.1.5を安定母体とした最小差分のUI改善候補\
**設計状態:** DESIGN DRAFT / 実装前

## 1. 背景・目的

現行Ver0.6.1.5では、kintone標準一覧の絞り込み条件を母集団として外注先負荷ヒートマップを表示している。機能としては正しいが、日常利用者が「特定の外注先だけを見たい」場合、kintone標準の絞り込み操作を理解している必要がある。

実運用では「田中鍛工＋山口製作所」のように複数外注先を同時比較したいケースも想定されるため、単一選択プルダウンではなく、**複数選択できる外注先クイックフィルタ**をヒートマップ画面内に追加する。

目的は、kintone標準絞り込みを置き換えることではなく、**標準絞り込みで決まった母集団の中から、外注先だけを簡単に追加絞り込みできるようにすること**である。

## 2. 基本方針

1.  Ver0.6.1.5を母体とし、既存機能を変更しない最小差分とする。
2.  kintone標準絞り込みは今後も正式な母集団条件として維持する。
3.  クイックフィルタはブラウザ内で `state.records`
    に対して適用し、選択のたびにkintone REST APIを再取得しない。
4.  複数外注先は **OR条件** とする。
5.  kintone標準条件との関係は **標準条件 AND 外注先クイック条件**
    とする。
6.  外注先が0社選択の状態は **全社表示** とする。
7.  Ctrl/Shiftキーを必要とするHTMLの `select multiple`
    は使用しない。チェックボックス付きドロップダウン方式とする。
8.  Ver0.6.1.5で確認済みの横スクロール、今日マーカー、表示期間、表示サイズ、入荷記録・取消、Manual表示等には手を入れない。

## 3. 画面仕様

### 3.1 配置

kintone標準一覧の操作領域の下、ヒートマップ本体の上部に、専用の2段目操作バーとして配置する。

想定表示:

``` text
外注先クイック絞り込み  [ すべての外注先 ▼ ]   全社表示
表示期間 [60日▼]   表示サイズ [標準▼]   対象 261件 / 外注先 31社
```

複数選択時:

``` text
外注先クイック絞り込み  [ 2社選択中 ▼ ]   [全解除]
  田中鍛工 ×   山口製作所 ×
```

既存の「一覧絞込：適用中／なし」表示は残す。

### 3.2 ドロップダウン展開

``` text
┌──────────────────────────────┐
│ 🔍 外注先名を入力                         │
├──────────────────────────────┤
│ ☑ 田中鍛工                               │
│ ☑ 山口製作所                             │
│ ☐ 山和（八尾）                           │
│ ☐ レイマック                             │
│ ...                                      │
├──────────────────────────────┤
│ 選択中 2社                     [全解除]   │
└──────────────────────────────┘
```

-   チェック操作は即時反映する。
-   検索文字は候補一覧だけを絞る。ヒートマップ条件そのものは変更しない。
-   外注先候補は、現在のkintone標準絞り込み後の `state.records`
    に存在する外注先から生成する。
-   候補名は重複排除し、日本語ロケールで名称順に並べる。
-   `（外注先未設定）`
    が母集団に存在する場合は候補として表示可能とする。

### 3.3 選択状態表示

-   0社: `すべての外注先`
-   1社: 選択した外注先名
-   2社以上: `N社選択中`
-   選択済み外注先はチップ表示し、各チップの `×` でも個別解除できる。
-   選択数が多い場合はUIが過度に縦長にならないよう、チップ領域は折返し＋最大高を設定する。

## 4. 絞り込み仕様

### 4.1 条件式

標準一覧条件を `K`、クイックフィルタ選択外注先を `V1...Vn` とした場合:

``` text
最終表示対象 = K AND (V1 OR V2 OR ... OR Vn)
```

ただし `n = 0` の場合:

``` text
最終表示対象 = K
```

### 4.2 実装上のデータ分離

`state.records` は **kintone標準絞り込み後の原母集団**
として保持し、クイックフィルタで直接書き換えない。

追加状態の例:

``` javascript
selectedQuickVendors: new Set()
```

描画時に派生配列を作る。

``` javascript
const visibleRecords = getQuickFilteredRecords(state.records);
```

これにより「全解除」でAPI再取得せず、元の標準絞り込み母集団へ即座に戻せる。

## 5. 各表示領域への適用範囲

クイックフィルタは画面全体で意味が揃うよう、次へ適用する。

  表示領域                    Ver0.6.1.6の動作
  --------------------------- --------------------------------------
  上段 外注先別ヒートマップ   選択外注先だけ表示
  対象件数／外注先数          クイック絞り込み後の件数・社数を表示
  日付矛盾／要注意カード      クイック絞り込み後の案件で再集計
  最大同時案件                クイック絞り込み後の外注先で再計算
  日程リスク一覧              クイック絞り込み後の案件だけ表示
  下段 案件詳細ガント         従来どおり1外注先をドリルダウン表示

### 5.1 下段案件詳細ガントの方針

Ver0.6.1.6では、**下段を複数外注先混在表示へ変更しない**。既存の「上段の外注先行をクリックすると、その1社の案件詳細へ切り替わる」操作を維持する。

理由:

-   複数外注先の比較目的は上段ヒートマップで満たせる。
-   下段を複数社混在へ変えると並び順・見出し・スクロール・入荷操作の回帰範囲が大きくなる。
-   Ver0.6.1.5を安定母体として維持するため、初回実装では責務を分離する。

クイック選択変更後、現在の `selectedVendor`
が表示対象外になった場合だけ、表示対象の先頭外注先へ安全に切り替える。対象0件なら下段は空表示とする。

将来、利用者から「選択した2～3社の案件を下段でも混在表示したい」という要望が確認された場合は、別バージョンで追加検討する。

## 6. kintone標準絞り込みとの連携

現行の `kintone.app.getQueryCondition()`
による標準条件取得・API再取得の仕組みは変更しない。

-   kintone標準絞り込み変更 → `index.show` 再発火 → 標準条件で
    `state.records` を再取得。
-   母集団が変わった時点でクイック外注先選択は
    **全解除へリセット**する。
-   リセット理由は、前の母集団にしか存在しない外注先が残り「0件になった」ように見える混乱を避けるため。
-   クイックフィルタ操作だけではAPI GETを行わない。

## 7. 外注先候補の取得元

外注先候補は別マスターや固定配列から作らず、`normalizeRecord()` 後の
`record.vendor` を使用する。

これにより、現在のコードが持つ外注先フィールド／fallbackの判定と一致し、「画面に存在する名称とフィルタ候補名が違う」問題を避ける。

## 8. 描画・イベント設計

### 8.1 追加予定関数

名称は実装時に最終決定するが、責務は以下に分ける。

``` text
getAvailableVendors(records)
getQuickFilteredRecords(records)
renderVendorQuickFilter(records)
bindVendorQuickFilterEvents(root)
reconcileSelectedVendor(visibleRecords)
```

### 8.2 render() の変更方針

現行:

``` text
state.records
  → buildVendorStats
  → Summary / Heatmap / Risk / Detail
```

Ver0.6.1.6:

``` text
state.records（標準絞り込み後の母集団）
  ↓
getQuickFilteredRecords()
  ↓
visibleRecords
  ├→ Summary
  ├→ Heatmap
  ├→ Risk
  └→ selectedVendorの妥当性確認 → Detail
```

`root.innerHTML` を再構築する既存設計は維持する。

### 8.3 スクロール保持

クイックフィルタ変更は既存の表示期間・表示サイズ変更と同じ
**UI内再描画** として扱う。

``` text
render(root, false)
```

を基本とし、Ver0.6.1で実装済みのスクロール位置保存・復元を利用する。クイックフィルタ変更のたびに「今日」へ強制ジャンプしない。

### 8.4 ドロップダウン開閉

-   ボタンクリックで開閉。
-   パネル外クリックで閉じる。
-   Escapeキーで閉じる。
-   チェック操作時は選択を維持したままパネルを閉じない。
-   再描画後も選択集合は `state` に残るため復元される。


## 8.5 Ver0.6.1.5 実コード突合せ結果と明示的変更箇所

ClaudeによるVer0.6.1.5実コード突合せレビューの結果、`state.records` には描画系の直接参照と、更新処理系の参照が混在していることを確認した。Ver0.6.1.6では、**描画用の母集団だけを `visibleRecords` に切り替え、取得済み原母集団としての `state.records` は保持する**。

特に、`renderHeader()` と `renderSummary()` には、引数で受け取る `vendorStats` とは別に、関数内部で `state.records` を直接参照する隠れた依存がある。これを残すと、ヒートマップ本体だけが絞られ、ヘッダー件数や要注意件数が全件のままになるため、明示的に引数化して修正する。

### 8.5.1 `state.records` 全参照箇所の扱い

| 位置（Ver0.6.1.5基準） | 内容 | Ver0.6.1.6での扱い |
|---|---|---|
| 145 | `fetchActiveRecords` の結果代入 | **変更しない**。標準絞り込み後の原母集団として保持 |
| 146 | `chooseInitialVendor(state.records)` | **変更しない**。初回フェッチ直後の初期選択処理 |
| 262 | `buildVendorStats(state.records, dates)` | **`visibleRecords`へ変更** |
| 282 | `renderRiskSummary(state.records)` | **`visibleRecords`へ変更** |
| 283 | `renderVendorDetail(state.records, ...)` | **`visibleRecords`へ変更**。描画母集団を統一 |
| 324 | `renderHeader()` 内 `state.records.length` | **隠れた依存。引数化して修正** |
| 417-418 | `renderSummary()` 内 `state.records.filter(...)` | **隠れた依存。引数化して修正** |
| 1004 | 入荷操作ハンドラ内 `state.records.find(...)` | **変更禁止。`state.records` のまま維持** |

### 8.5.2 `renderHeader()` の修正方針

現状のように `state.records.length` を内部参照せず、描画対象レコード数を明示的に渡す。

例:

```javascript
renderHeader(vendorStats, visibleRecords)
```

または、

```javascript
renderHeader(vendorStats, visibleRecords.length)
```

とし、ヘッダーの `対象 N件` はクイックフィルタ後の件数を表示する。

### 8.5.3 `renderSummary()` の修正方針

`renderSummary(vendorStats)` 内部で `state.records.filter(...)` している日付矛盾／要注意件数は、`visibleRecords` を引数として受けて集計する。

例:

```javascript
renderSummary(vendorStats, visibleRecords)
```

これにより、上段ヒートマップ・対象件数・要注意件数の母集団を完全に一致させる。

### 8.5.4 入荷操作系は `state.records` を維持する

入荷登録・修正・取消のクリックハンドラにある、

```javascript
state.records.find(r => String(r.id) === recordId)
```

は **絶対に `visibleRecords` に置き換えない**。

理由:

1. `visibleRecords` は `render()` 内で生成する派生配列であり、別イベントハンドラから直接参照する前提ではない。
2. 入荷操作の対象レコード探索は、画面上のクイックフィルタ状態とは独立して、取得済み原母集団から確実に行うべきである。
3. 機械的一括置換による更新機能の回帰を防ぐため、この箇所は実装レビュー時の明示的な「変更禁止箇所」とする。

### 8.5.5 実装禁止事項

- `state.records` → `visibleRecords` の一括置換を行わない。
- `fetchActiveRecords()` 後の `state.records` 自体をクイックフィルタ済み配列で上書きしない。
- 入荷操作・取消・修正など既存更新系のレコード探索ロジックへクイックフィルタを混入させない。


## 9. 状態保持

Ver0.6.1.6初版ではクイック外注先選択を `localStorage` に保存しない。

-   画面再読込: 全社表示へ戻る。
-   kintone標準絞り込み変更: 全社表示へ戻る。
-   表示期間／表示サイズ変更: 選択状態を維持。
-   上段外注先行クリック: クイック選択状態は維持し、下段の
    `selectedVendor` だけ変更。

「前回選択した外注先を次回も保持したい」という要望が出た場合のみ、後続版で保存機能を検討する。

## 10. 0件・例外時の表示

-   クイック条件適用後0件になった場合、ヒートマップ・リスク・下段は既存の空表示を利用する。
-   件数表示は `対象 0件 / 外注先 0社` とする。
-   フィルタバーには選択状態を残し、利用者が `全解除` できるようにする。
-   候補検索で0件の場合は `該当する外注先がありません` と表示する。
-   外注先名は既存の `escapeHtml` / `escapeAttr`
    を通し、DOMへ生文字列を直接埋め込まない。

## 12. API・更新安全性

クイックフィルタは表示専用機能とし、フィルタ操作ではPUT/POST/DELETEを一切実行しない。

入荷記録等、既存の更新操作は従来どおりその専用イベントからのみ実行する。クイックフィルタ追加を理由に更新APIのコードは変更しない。

## 17. 判定

### 17.1 実コード突合せレビュー結果

Claude実コードレビュー判定は **GO WITH CONDITIONS**。

条件は以下の2点。

1. `renderHeader()` と `renderSummary()` に残る隠れた `state.records` 直接参照を、`visibleRecords` を明示的に受け取る形へ修正すること。
2. 入荷操作ハンドラ内の `state.records.find(...)` は変更対象外として明記し、既存の更新処理を保護すること。

上記を本Rev.2で正式な実装条件として反映済みとする。


本仕様では、利用者がkintone標準絞り込みを操作しなくても、日常的な「この外注先だけ見たい」「この2～3社を比較したい」をヒートマップ画面内で完結できる。

一方で、標準絞り込みは正式な母集団条件として残すため、既存のVer0.6.1.5の設計思想を崩さない。**Ver0.6.1.6は「外注先だけを簡単に追加絞り込みする表示専用UI」として実装する**ことを正式設計案とする。
