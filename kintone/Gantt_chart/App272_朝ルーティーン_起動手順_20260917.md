# App272 朝ルーティーン 起動手順
更新日: 2026-09-17

## 1. 目的

`Run-App272-MorningRoutine_v0.1.ps1` を使って、朝の外注課納期管理CSV取込を一連の流れで実行する。

現時点の v0.1 では、次の処理をまとめて行う。

1. NAS上の当日CSVを取得
2. ローカルへコピー
3. App272取込用CSVへ整形
4. 新規POSTのDryRun
5. DryRun結果から新規POを自動抽出
6. `-ExecuteNew` 指定時のみ、新規POSTを本番実行
7. 既存レコードPUTのDryRun
8. 既存更新候補を表示して停止

> 既存PUTは、現時点では自動Executeしない。Phase Bの全ケース確認後に統括版へ組み込む。

---

## 2. 使用スクリプト

```text
C:\HPDB\Run-App272-MorningRoutine_v0.1.ps1
```

内部で使用する主なスクリプト:

```text
C:\HPDB\Format-KonyuCSV_RFC_yyyyMMdd_v2.ps1
C:\HPDB\Import-App272_Phase1C_New_v0.7.4_MasterAuto.ps1
C:\HPDB\Import-App272_PhaseB_Update_v0.8.0.5_PROD.ps1
```

---

## 3. 起動方法

PowerShellを開き、まず作業フォルダへ移動する。

```powershell
cd C:\HPDB
```

初回実行時、またはChatGPT等から更新版を保存した直後は、ブロック解除を行う。

```powershell
Unblock-File .\Run-App272-MorningRoutine_v0.1.ps1
```

通常の朝実行は次の1行。

```powershell
.\Run-App272-MorningRoutine_v0.1.ps1 -ExecuteNew
```

---

## 4. APIトークン入力

処理途中で次の2種類のAPIトークンを手入力する。

```text
App270 READ ONLY API Token
App272 PROD API Token
```

役割:

- App270: 手配書番号参照・旧ルックアップ制約確認用。READ ONLY。
- App272: 本番アプリ272への新規POST、および既存PUT DryRun確認用。

APIトークンは画面上には表示されない。

---

## 5. 当日CSV

標準では、実行日の年月日からNAS上のファイルを自動判定する。

例: 2026-09-18

```text
\\192.168.0.35\disk\RPA-DATA\外注課\外注課納期管理_20260918.csv
```

ローカルコピー:

```text
C:\HPDB\外注課納期管理_20260918.csv
```

整形後:

```text
C:\HPDB\外注課納期管理_20260918_整形済み.csv
```

---

## 6. 正常時の処理順

```text
NAS当日CSV
   ↓
ローカルコピー
   ↓
CSV整形
   ↓
Phase1C 新規POST DryRun
   ↓
新規PO集合を自動確定
   ↓
Phase1C 新規POST Execute
   ↓
POST後再GET・検証
   ↓
PhaseB 既存PUT DryRun
   ↓
更新候補一覧を表示
   ↓
停止
```

---

## 7. 新規POSTの安全条件

新規POSTは、DryRunで抽出された新規PO集合をそのまま `ExpectedNewPo` として本番実行する。

内部では以下を確認する。

- 新規PO件数
- PO重複なし
- `MaxNew` 超過なし
- Vendor / Staff不足
- App270参照
- App272既存重複
- POST後の再GET
- 基幹9項目
- 対象K日程項目

POST後の検証でエラーが出た場合は安全停止する。

---

## 8. 既存PUTについて

現時点の `Run-App272-MorningRoutine_v0.1.ps1` は、既存PUTをDryRunまで実行する。

自動Executeはしない。

理由:

- Phase Bは U12 / U1 / U2 まで確認済み
- App270ルックアップ制約対応済み
- Manual保護確認済み
- Batch再計算確認済み
- ただし、全ケースを統括版として自動Executeする最終確認は未完了

したがって、朝ルーティーンの最後に表示される更新候補を確認してから、必要に応じて既存PUTを別途実行する。

---

## 9. App270ルックアップ制約

旧プラグインの制約により、手配書番号はApp270に実在している必要がある。

既存PUTで `ルックアップ` を変更する場合は、

```text
App272 PROD API Token
App270 READ ONLY API Token
```

の両方を使用する。

App270への書込みは行わない。

---

---

## 11. エラー時

次のような場合は、そのまま再実行せず原因を確認する。

- NAS当日CSVが見つからない
- 整形スクリプトが見つからない
- CSV整形失敗
- 新規PO重複
- `MaxNew` 超過
- App270手配書番号不在
- Vendor / Staff不整合
- App272重複
- APIエラー
- POST後検証不一致
- Phase B SafetyStop

エラー発生時は、表示されたログと `C:\HPDB\logs` の最新ファイルを確認する。

## 12. 今後の完成形

最終的には以下を1本の朝ルーティーンとして完成させる予定。

```text
NAS取得
→ CSV整形
→ 新規POST DryRun
→ 新規POST Execute
→ 既存PUT DryRun
→ 既存PUT Execute
→ 最終再GET検証
→ ログ保存
→ 完了
```

APIトークンは、現在の運用方針どおり実行時に手入力する。
