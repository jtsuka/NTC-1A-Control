## 2. 不具合1：日付確認UIのラベルが縦一文字に折り返される

### 2.1 症状

「入荷しました」ボタン押下後に表示される日付確認UI内で、ラベル文字列「外注入荷日」が

```text
外
注
入
荷
日
```

のように1文字ずつ縦に折り返され、可読性を失っていた。標準・大・特大いずれの表示サイズでも
発生し、特大表示でもわずかに改善する程度で解消しなかった。

### 2.2 原因

日付確認UIを、既存の手配書番号列（幅120〜160px、`--eh-col-order-w`）の内側で
`flex-basis:100%`として伸ばす実装になっていたため、そもそも列の絶対的な横幅が不足していた。

加えて、ラベルの見出しテキスト「外注入荷日」が`<label>`要素内に**裸のテキストノード**として
`<input>`と並べて置かれており、`white-space:nowrap`を親要素へ指定しただけでは、
テキストノード自体への適用が不安定になる場合があった。

### 2.3 対応

1. テキストを明示的な`<span class="eh-receipt-editor-label-text">`で囲み、
   そのspanへ直接`white-space:nowrap; flex:0 0 auto;`を指定した
2. 日付確認UI自体を、後述の不具合2の対応と合わせて、列幅に縛られない
   固定幅（220px）の独立したカードへ変更した

## 3. 不具合2：ポップアップが押した行と無関係な場所に表示される

### 3.1 症状

不具合1を幅の問題として対応した後（`position:absolute`＋列を基準にした浮き出し表示）、
日付確認UI自体は正しい内容・正しい見た目で表示されるようになったが、**表示される位置が
クリックした行と一致せず**、無関係な行の下やスクロール範囲外に表示され、
「ボタンを押しても出てこない（実際には見えない場所に表示されている）」という状態になった。

`document.querySelector('.eh-receipt-editor').getBoundingClientRect()`で確認したところ、
要素自体は正しい内容で生成されており、DOM上に存在していたが、画面上の座標が
クリックした行の位置と対応していないことが確認された。

### 3.2 原因

日付確認UIの位置決めを、`position:sticky`が指定された列（手配書番号列）を基準にした
`position:absolute`のCSSに頼っていた。`position:sticky`は仕様上、絶対配置の基準
（containing block）になり得るが、ブラウザによっては「stickyが画面上に固定されている
見た目上の位置」ではなく「stickyが無かった場合の静的な位置」を基準に計算される場合があり、
これがクリックした行と無関係な位置にポップアップが表示される原因となっていた。

### 3.3 対応

CSSの相対配置に頼る方式を廃止し、**JavaScriptでクリックされたボタンの実際の画面座標
（`getBoundingClientRect()`）を計算し、その数値をそのまま指定する方式**へ変更した。

```text
変更前: .eh-receipt-editor { position:absolute; top:100%; left:4px; }
        （手配書番号列のposition:stickyを基準に相対配置）

変更後: JS側で sourceButton.getBoundingClientRect() を取得し、
        editor.style.top / editor.style.left へ画面座標を直接設定
        （position:fixed、document.body直下へ配置）
```

これに伴い、以下も合わせて変更した。

- 日付確認UIは`document.body`直下へ配置する（元の行・列のDOM構造からは独立させる）
- 画面の右端・下端にはみ出す場合、右端では折り返し、下端で切れる場合は
  ボタンの上側へ表示し直す簡易補正を追加した
- 同時に開けるUIは1つのみとし、外側クリックで自動的に閉じるようにした
  （行の中に埋め込む方式では不要だった配慮だが、独立した浮き出し表示にしたことで必要になった）
- 保存成功時・キャンセル時とも、確実にUIが閉じることを確認した

## 4. 変更しなかったもの（確認事項）

以下は今回の修正の前後で変更していないことを確認済み。

- PUT対象は`外注入荷実績日`のみ（他フィールドへの書込みなし）
- `$revision`によるガード方式
- 保存中の行単位disable
- `event.stopPropagation()`によるレコードリンク／行クリックとの競合防止
- K加工着手日・K完成検査日・K暫定設定・K日程種別・K計算根拠への非接触
- 保存成功後は`render()`全体を呼ばず、該当行のみのピンポイントDOM更新とする方針
- 上段ヒートマップの負荷計算への非影響

## 6. 今後の参考事項

`position:sticky`を基準にした`position:absolute`は、ブラウザ実装によって
挙動が変わりうるため、**sticky要素の内部に、位置合わせが重要なポップアップ的UIを
新たに追加する場合は、本件と同様にJavaScriptで実座標を計算するfixed配置を
優先して検討する**こと。今後、外注先別暫定日程設定や他のガント関連UIで
同種のポップアップ・吹き出し要素を追加する際も、本仕様書を参照すること。
