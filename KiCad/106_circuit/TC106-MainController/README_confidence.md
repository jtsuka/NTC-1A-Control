# TC106_Main_Comm_Reconstruction — 再構築メモ (Rev.3, 訂正版)

## Rev.3の訂正（重要）
**Rev.2の「命名規則不一致」という結論は誤りでした。撤回します。**

ユーザーからの再指示を受け、R1/R3からpin11/12への配線をピクセル単位で再々トレースしたところ、**見落としていた交差**を発見しました。

```
R1(Q1/ch1送信側) の縦配線は R3 の縦配線より右側を通り、より下まで伸びて
  下側の水平線(pin12/RC1)に接続
R3(Q2/ch2送信側) の縦配線は短く、上側の水平線(pin11/RC0)に接続
```

**訂正後の確定配線:**
- ch1送信(Q1/R1) → **pin12 (RC1)** = ASMの`tx_ch1 equ 1`と一致
- ch2送信(Q2/R3) → **pin11 (RC0)** = ASMの`tx_ch2 equ 0`と一致

Rev.2では「PDFのシルク印字と ASM変数名の対応が逆」という命名規則の不一致として処理しましたが、これは**私のピクセルトレース自体が交差を見落としていたことによる誤り**でした。チャッピーの最初の指摘（ASMとの対応が逆）が正しく、私の初回トレースが間違っていました。

## 教訓
pin11/pin12のように隣接ピンへの配線が近接して交差する箇所は、目視での「交差なし」判定を過信せず、今回行ったような高倍率での縦配線の左右関係の確認を最初から徹底すべきでした。Direction-B側(pin18/17)で使った「水平線を水平方向にストリップ状に切り出して辿る」手法を、TX側でも最初から使うべきでした。
