# 船舶値付用紙 VBA / PowerShell 項目比較Log仕様 — Claudeクロスレビュー依頼

## 1. 目的
Excel VBA版「船舶値付用紙」と PowerShell版 `Print-ValueTag_v0.10.6_VBAFit.ps1` は、2026-09-16の同一実CSVを用いたDocuWorks→PDF比較で40手配/40ページが順不同で1対1対応し、実質的な帳票内容差の新規検出なしまで到達した。

次フェーズではPDF画像比較より一段強い保証として、VBAとPSが**帳票へ渡す最終状態を項目単位で機械比較**したい。

**重要：今回は仕様レビューのみ。添付VBA/PSのコードは変更しないでください。**

## 2. レビューしてほしい結論
主比較単位を次とする案が妥当か、VBA原典・setting・PS実装を独立に確認してレビューしてください。

> 論理位置（BJ12等） × 項目情報 × 帳票へ渡す最終値

物理X/Y座標は第一比較キーとせず、既存PDF画像比較の領域とする案です。

## 3. FINALログ案
1レコード = 「1手配・1ページ・1明細・1論理位置の最終状態」。VBA/PSが同一列構成CSVを出力し、順不同で比較します。

| 列 | 内容 | 例 |
|---|---|---|
| Engine | 出力元 | VBA / PS |
| OrderNo | 比較用に正規化した受注番号 | E269074470 |
| PageInOrder | 手配内ページ | 1 |
| DetailNo | 手配内明細。HEADER等は0 | 3 |
| Area | HEADER / BODY | BODY |
| Position | setting/帳票上の論理位置 | BJ12 |
| SourceId | setting/CSV項目ID。派生値は代表IDまたは空欄 | 211 |
| SourceName | 項目名 | 製造原価_金額 |
| RawValue | 加工前入力値（診断補助） | 9617 |
| FinalValue | **帳票へ渡す直前の最終値** | 空欄 |
| Visible | 最終表示対象 | 0 / 1 |
| Rule | 最終値を決めた主要ルール | BJ12通常値抑止 |

基本比較キー案：

`OrderNo + PageInOrder + DetailNo + Area + Position`

**SourceIdは主キーにしない**案です。同じPositionへ複数SourceId/派生処理が上書きするため、比較したいのは最終的にその位置へ残る値だからです。

## 4. BJ12実例（この仕様が必要になった理由）
2026-09-16実データ `E269074470` では、CSVに製造原価金額 `9617` 等が存在するにもかかわらず、数量1の通常明細でVBA最終帳票のBJ12は空欄でした。

v0.10.5ではsetting由来のBJ12(id=211)が残り、PSだけ右側へ製造原価金額を二重表示しました。v0.10.6でBJ12を一旦除去し、警告を設定後、数量>1かつ製造原価単価>0の場合だけ製造原価合計をBJ12へ再設定することでPDF表示がVBAと一致しました。

したがってRawValue比較だけでは検出できず、FinalValue比較が必要です。

```text
VBA vs PS v0.10.5
RawValue=9617
VBA FinalValue=""
PS  FinalValue="9617"  -> DIFF

VBA vs PS v0.10.6
RawValue=9617
VBA FinalValue=""
PS  FinalValue=""      -> MATCH
```

## 5. 値の正規化案
- Null / 未設定 / 空文字は比較上の空欄表現へ統一。
- FINAL比較は原則として**帳票へ渡す表示文字列**を比較。
- 金額のカンマ、`￥`、括弧、警告記号は帳票仕様の一部なのでFinalValueから除去しない。
- 日付は帳票へ渡す最終表記を比較。
- OrderNoだけは比較キー用途としてハイフン有無等を共通形式へ正規化。
- 前後空白、全角半角、改行を自動正規化すると原典差を隠す可能性があるため、初期案は原則保持。

## 6. TRACEログ案
初回から全項目TRACEは実装しない。FINALでDIFFになった項目だけ、将来TRACEを有効化できる設計とする。

想定列：処理順、Position、BeforeValue、AfterValue、SourceId、Rule。

BJ12のような「同一位置への複数上書き」の原因追跡用です。

## 7. FINALとPDF画像比較の役割分担
FINALログ対象：文字、数値、日付、警告、派生表示、空欄化、論理的表示状態。Gray8はStyle/Mask列追加候補。バーコードは表示文字列/エンコード元値をログ対象にする案を検討。

PDF画像比較側：フォント実座標、罫線、バーコード線幅、ExcelとGDI+のレンダリング差など。

## 8. 実装安全条件
- 原典VBAの業務処理・セル転記・印刷条件を変えない。
- Logは比較試験時だけ有効化できる方式を優先。
- Log出力失敗が帳票出力結果を変えない構造にする。
- VBA/PSで同じCSV列定義・文字コード・改行仕様を使う。
- 初回母集団はPDF比較PASS済みの2026-09-16実データ40件を再利用。
