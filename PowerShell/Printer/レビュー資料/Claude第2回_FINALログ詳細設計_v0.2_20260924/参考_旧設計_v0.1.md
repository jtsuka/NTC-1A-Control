# 船舶値付 VBA→PowerShell FINALログ比較　詳細設計書
版: 0.1 / 2026-09-24
目的: 原典VBAの業務ロジックを変更せず、最終出力値・論理位置・座標を観測し、PowerShell版のCheckLogと機械比較できる証拠を作る。

---

## 1. この工程の位置づけ

原価割れ注意は v0.10.9 で Stage 1人工試験A～E 5/5 PASS、Stage 2当日実データ回帰で
v0.10.8/v0.10.9 CheckLogがバイト完全一致し、FINAL CLOSED済みである。

今回の工程は原価割れを再検討するものではない。
船舶値付VBA→PowerShell移行全体をFINAL CLOSEDするため、
「原典VBAが最終的にどのセルへ、何を、どの座標で出力したか」を観測可能にし、
PS版の描画ログと比較するための独立した検証工程である。

---

## 2. 最重要原則

### 2.1 原典は絶対に上書きしない
元ファイル:
`@(自動)企画室 船舶値付用紙出力(8).xlsm`

このファイルは保存・編集しない。
Windows上で複製して、例として次の名前を使用する。

`@(検証用_FINALログ)企画室 船舶値付用紙出力_20260924.xlsm`

VBA変更はこの検証コピーだけに行う。

### 2.2 業務ロジックを変更しない
禁止:
- If条件の変更
- DATA_DIC / MODEL_DIC / FLAG_DIC の値変更
- BT_NO判定の変更
- Sort / Find / FindNext順序の変更
- セルへの転記順序変更
- PrintArea / PageSetup / Zoom変更
- PrintOut順序変更
- 値のTrim、Format、Replace等をログの都合で本体側に追加
- 警告優先順位変更
- 印刷セルを別セルへ移す
- VBA側の結果をPSへ合わせる「修正」

許可:
- 観測専用標準モジュール `modCheckLog` の追加
- 最終転記直後に `CheckLog_Write...` を呼ぶ
- PrintOut直前/直後にページ・手配単位の観測情報を記録する
- エラー時にログ側だけを無効化し、原典処理を継続させる

### 2.3 ログ障害で本番ロジックを止めない
ログは観測器であり、本体ではない。
ログフォルダ作成失敗、CSV書込み失敗等で原典VBAの帳票処理を停止させてはならない。
ログ関数内部は局所的な `On Error GoTo EH` とし、呼出元へエラーを伝播させない。

## 3. 比較したいもの

最終比較キーの基本形:

`OrderNo + PageInOrder + DetailNo + Area + Position`

比較属性:

- SourceId
- Value
- X
- Y
- Width
- Height

推奨VBAログ列:

|列|意味|
|---|---|
|RunId|1回の実行を識別|
|BT_NO|用途区分。船舶は2|
|OrderNo|受注番号|
|PageInOrder|手配内ページ番号|
|DetailNo|明細番号。HEAD等は空欄可|
|Area|TOP / HEAD / BODY|
|Position|setting表記の論理セル位置。例 BJ12|
|SourceId|元DL列番号/field id。派生値はDERIVED等も可|
|Value|最終的に帳票へ転記された文字列|
|X|Excel Range.Left|
|Y|Excel Range.Top|
|Width|表示領域の幅|
|Height|表示領域の高さ|
|MergeAddress|結合セルなら結合範囲|
|SheetName|出力シート|
|Timestamp|ログ時刻|

重要:
座標の単位はExcel VBAの `Range.Left/Top/Width/Height` がポイント。
PS側CheckLogもpx→pt変換しているため、ポイントで比較する。

## 4. MergeAreaの扱い

結合セルでは、単一セルの `.Width` ではなく、実際の表示領域全体を採る必要がある。

安全な考え方:

```vb
If target.MergeCells Then
    Set logRange = target.MergeArea
Else
    Set logRange = target
End If

x = logRange.Left
y = logRange.Top
w = logRange.Width
h = logRange.Height
```

禁止:
- `target.Width` と `target.MergeArea.Width` を混在させる
- MergeAreaの左上以外を別セルとして重複記録する

結合セルは `MergeArea.Cells(1,1)` を代表セルとする。

## 5. modCheckLog 新規追加設計

VBEで「挿入 → 標準モジュール」を選び、モジュール名を `modCheckLog` とする。

### 5.1 モジュール変数

```vb
Option Explicit

Private mEnabled As Boolean
Private mFileNo As Integer
Private mLogPath As String
Private mRunId As String
Private mOpened As Boolean
```

### 5.2 初期化

```vb
Public Sub CheckLog_Begin(ByVal baseFolder As String)
    On Error GoTo EH

    mEnabled = True
    mRunId = Format(Now, "yyyymmdd_hhnnss")
    mLogPath = baseFolder & "\VBA_FINAL_CheckLog_" & mRunId & ".csv"

    CheckLog_EnsureFolder baseFolder

    mFileNo = FreeFile
    Open mLogPath For Output As #mFileNo
    mOpened = True

    Print #mFileNo, _
        "RunId,BT_NO,OrderNo,PageInOrder,DetailNo,Area,Position,SourceId,Value,X,Y,Width,Height,MergeAddress,SheetName,Timestamp"
    Exit Sub

EH:
    mEnabled = False
    mOpened = False
    Err.Clear
End Sub
```

### 5.3 終了

```vb
Public Sub CheckLog_End()
    On Error Resume Next
    If mOpened Then Close #mFileNo
    mOpened = False
    mEnabled = False
End Sub
```

### 5.4 フォルダ作成

`EnsureFolderExists` は本体側の既存関数へ依存させず、ログモジュール内で完結させる。
既存関数と同名にしない。

```vb
Private Sub CheckLog_EnsureFolder(ByVal folderPath As String)
    On Error GoTo EH
    If Len(Dir(folderPath, vbDirectory)) = 0 Then
        MkDir folderPath
    End If
    Exit Sub
EH:
    Err.Clear
End Sub
```

※ 多階層を一度に新規作成する必要がある場合は親から順に作成する版へ変更する。
今回推奨フォルダは既存 `C:\HPDB\船舶値付用紙` 配下なので、
`C:\HPDB\船舶値付用紙\VBA_CheckLog` の1階層だけを作る構成を推奨。

### 5.5 CSVエスケープ

```vb
Private Function CheckLog_Csv(ByVal v As Variant) As String
    Dim s As String
    s = CStr(v)
    s = Replace(s, , "")
    CheckLog_Csv =  & s & 
End Function
```

値中のカンマ、改行、ダブルクォートを壊さないため、文字列項目は必ずRFC4180型で引用する。
改行を保持するか `
` へ正規化するかは比較仕様としてClaudeレビューで確定する。
推奨は「値そのものは保持し、比較ツール側でCSVとして正しく読む」。

### 5.6 1セルの最終値記録

```vb
Public Sub CheckLog_WriteFinal( _
    ByVal btNo As Variant, _
    ByVal orderNo As String, _
    ByVal pageInOrder As Variant, _
    ByVal detailNo As Variant, _
    ByVal areaName As String, _
    ByVal positionName As String, _
    ByVal sourceId As Variant, _
    ByVal target As Range)

    On Error GoTo EH

    If Not mEnabled Then Exit Sub
    If Not mOpened Then Exit Sub
    If target Is Nothing Then Exit Sub

    Dim r As Range
    If target.MergeCells Then
        Set r = target.MergeArea
    Else
        Set r = target
    End If

    ' 結合範囲は左上セルだけを代表として記録
    If target.Address <> r.Cells(1, 1).Address Then Exit Sub

    Dim finalValue As String
    finalValue = CStr(r.Cells(1, 1).Value)

    Print #mFileNo, _
        CheckLog_Csv(mRunId) & "," & _
        CheckLog_Csv(btNo) & "," & _
        CheckLog_Csv(orderNo) & "," & _
        CheckLog_Csv(pageInOrder) & "," & _
        CheckLog_Csv(detailNo) & "," & _
        CheckLog_Csv(areaName) & "," & _
        CheckLog_Csv(positionName) & "," & _
        CheckLog_Csv(sourceId) & "," & _
        CheckLog_Csv(finalValue) & "," & _
        CStr(r.Left) & "," & _
        CStr(r.Top) & "," & _
        CStr(r.Width) & "," & _
        CStr(r.Height) & "," & _
        CheckLog_Csv(r.Address(False, False)) & "," & _
        CheckLog_Csv(r.Worksheet.Name) & "," & _
        CheckLog_Csv(Format(Now, "yyyy/mm/dd hh:nn:ss"))

    Exit Sub
EH:
    ' 観測失敗は原典処理へ影響させない
    Err.Clear
End Sub
```

## 6. どこでログを呼ぶか

最重要ポイント。
「元データを読み込んだ時」ではなく、**VBAが帳票セルへ最終値を書き込んだ直後**に採る。

理由:
- 原価未入力
- 売価未入力
- 原価割れ
- 製造原価合計
- Y受注金額注意
- AV5
- A7
などは途中値ではなく、優先順位・派生処理を経た「最終表示値」を比較する必要があるため。

### 6.1 BODY
原典の setting BODY 行43～80を `Find/FindNext` 等で処理し、
実際の出力セルへ値を代入している箇所の**直後**に呼ぶ。

概念:

```vb
target.Value = finalValue

Call CheckLog_WriteFinal( _
    BT_NO, _
    orderNo, _
    pageInOrder, _
    detailNo, _
    "BODY", _
    positionName, _
    sourceId, _
    target)
```

注意:
ログのために `finalValue` を再計算しない。
**必ず targetへ書かれた後、target自身から値を読み返す。**

これによりBJ12の競合（id=12/211等）も最終結果だけを観測できる。

### 6.2 TOP / HEAD
同様に、TOP/HEADの最終転記ループでセル代入直後に記録する。
DetailNoは空欄でよい。

### 6.3 派生セル
AV5、BJ12警告等のようにsourceId一つで表せない場合、
SourceIdは原典で使用している借用IDをそのまま記録するか、
別途 `DERIVED` を記録する。

ただしPSとの比較キーはSourceIdを主キーにしない。
主キーは:
`OrderNo + PageInOrder + DetailNo + Area + Position`
とする。

SourceIdは「なぜその値になったか」の診断情報として扱う。

## 7. PageInOrderの決め方

VBAの内部PrintOut順と、最終紙束/PDFの順序は過去に差がある。
したがってPageInOrderは「実行全体の通しページ番号」ではなく、
**1手配の中で何ページ目か**を記録する。

例:
- E...001 / 1ページ目 → PageInOrder=1
- E...001 / 2ページ目 → PageInOrder=2
- 次の手配 → 再び1

11明細以上の手配では必須。

ページ番号をログのために推測しない。
原典がPrintArea/PrintTitleRows/PrintOutを確定させる箇所の既存ループ変数から取得する。
既存変数が無い場合のみ、検証コピー側で観測用カウンタを追加する。
そのカウンタは印刷条件・処理分岐には絶対に使わない。

---

## 8. Positionの定義

PositionはExcelの実アドレスではなく、これまでの比較仕様どおり**setting表記の論理位置**を優先する。

例:
- BJ12
- AS12
- AV5
- A7

理由:
PS側は帳票論理セルをキーとしてCheckLogを出している。
VBAの作業シート上で物理アドレスが変化しても論理位置が一致すれば比較可能。

MergeAddressは別列に持つ。

## 9. ログ開始/終了の組込み

### 開始
船舶処理開始時、BT_NO=2が確定した後で1回だけ:

```vb
Call CheckLog_Begin("C:\HPDB\船舶値付用紙\VBA_CheckLog")
```

ただし最終的な挿入位置は原典VBAのエントリポイントをClaudeと再確認して決める。

### 終了
正常終了経路で:

```vb
Call CheckLog_End
```

さらにエラー終了経路にも:

```vb
Call CheckLog_End
```

を入れる。

ただし既存の `On Error` 構造を書き換えない。
既存エラーハンドラがあるなら、その出口直前に1行追加する。

## 11. 最初に行う安全試験 T0

本番データを使う前に、ログ追加が帳票を変えていないことを確認する。

同じ人工データを:
A. ログ無し原典VBA
B. ログ有り検証コピーVBA
でDocuWorksへ出力。

判定:
- ページ数同一
- 表示内容同一
- 改ページ同一
- 印刷順同一
- ログ有り側だけCSVが生成される

差があれば即FAIL。
ログ機能を直す。原典ロジック側を直してはいけない。

## 13. VBAログとPSログの正規化

両者の生ログ形式は完全一致させる必要はない。
比較前に正規化CSVを作る。

推奨正規化列:

`OrderNo,PageInOrder,DetailNo,Area,Position,SourceId,Value,X,Y,Width,Height`

### 13.1 Value
- バーコードは文字列比較
- 数字を勝手に数値化しない
- 先頭0を保持
- 全角/半角を勝手に正規化しない
- 改行は比較ツール内で同じ表現へ正規化してよいが、原ログは保持

### 13.2 座標
VBAはポイント。
PSもポイント。
浮動小数誤差を考慮し、まず完全一致ではなく許容差で判定する。

初期推奨:
- X/Y: ±0.5 pt
- Width/Height: ±0.5 pt

ただし許容差は実測分布を見て最終決定し、
「合わないから後から広げる」ことは禁止。

### 13.3 キー
基本:
`OrderNo + PageInOrder + DetailNo + Area + Position`

同一キーが複数発生した場合は自動PASSにしない。
重複一覧を出し、Find/FindNext順やBJ12競合を調査する。

## 14. 比較結果の分類

PASS:
- キー集合一致
- Value一致
- 座標が許容差内

VALUE_DIFF:
- 同一キーだがValue不一致

POSITION_DIFF:
- Valueは同じだが座標差が許容外

VBA_ONLY:
- VBAにだけ存在

PS_ONLY:
- PSにだけ存在

DUPLICATE_KEY:
- 同一側で比較キー重複

PAGE_DIFF:
- 手配内ページ番号/ページ構成不一致

---

## 15. 合格条件

FINALログ比較をPASSとする条件:

1. 対象手配集合一致
2. ページ構成一致
3. 比較キー集合一致
4. Value差分0件
5. VBA_ONLY=0
6. PS_ONLY=0
7. DUPLICATE_KEY=0、または原典仕様として説明済みで比較方法が確定
8. 座標差分が事前確定した許容範囲内
9. バーコード文字列一致
10. 自由記述文字列一致
11. ログ有無でVBA帳票結果が変化しない（T0 PASS）

---

## 16. 失敗時の原則

差分が出てもPSをすぐ修正しない。

順序:
1. ログ採取ミスか確認
2. Position/DetailNo/PageInOrder対応付けミスか確認
3. MergeArea差か確認
4. 原典VBAの実挙動を確認
5. PS仕様書と過去CLOSED証拠を確認
6. 本当にPS実装差なら修正候補化

CLOSED済み仕様を、1件のログ差だけで再オープンしない。
再オープンには「ログ機構の問題ではない」と確認できる実証が必要。

## 17. Claudeクロスレビューで特に見てほしい点

1. 原典VBAの「最終転記箇所」がどこか。ログ呼出し位置はそこだけで十分か。
2. setting BODY 43～80 / Find・FindNextの探索順を壊さない挿入位置か。
3. BJ12 id=12/211競合で「途中値」ではなく最終値を採れるか。
4. TOP/HEAD/BODYそれぞれのPosition/DetailNo取得方法。
5. 11明細以上でPageInOrderを正確に採る方法。
6. `MergeArea.Width/Height`の取得方法。
7. `On Error`追加が既存エラー制御を変えないか。
8. CSV内改行/ダブルクォートの扱い。
9. `Print #`で日本語・CP932出力することが比較上問題ないか。UTF-8が必要なら安全な方法。
10. ログ関数呼出しによって計算/再描画/Selection/ActiveCell等の副作用が起きないか。
11. SourceIdを比較キーから外す方針の妥当性。
12. PS CheckLogのX/Y/Width/HeightとVBA Range座標の原点・Zoom・余白差をどう扱うべきか。
13. T0（ログ無し原典 vs ログ有り検証コピー）で最低限比較すべき項目。
14. 原典を一切変更しないという意味を「原典ファイル保存禁止、検証コピーのみ変更」とする運用の妥当性。
