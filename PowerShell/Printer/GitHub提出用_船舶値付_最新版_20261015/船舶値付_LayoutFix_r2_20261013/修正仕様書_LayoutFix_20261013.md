## 1. 目的

原典VBAの印刷結果と、PS版の印刷結果の**印字位置**を揃える。印字する値・内容（CheckLog）は変えない（円記号を除く）。

判定基準（2026-10-13 ユーザー承認）：同じ要素の印字位置の差が **横4mm以内・縦2mm以内**。

| 原因 | 内容 | 規模 |

| ① 整列の無視 | PSは全セルを `DrawString(x0+3, y0+1)` で左寄せ描画していた。テンプレートの中央寄せ77セル・右寄せ14セルが反映されていなかった | 商品名で約40mm左など |
| ② 整列定義の欠落 | `label_layout_full.json` に、原典ブックの model シートで横位置が設定されている33セルの情報が無かった | 商品名・行番号・数量など |

## 3. 修正内容

### 3.1 整列を反映して描画（スクリプト）
- セル定義の `align.h` が `center` / `right` のとき、結合セル全体（x0〜x1）を基準に `StringFormat`（Center / Far）で描画する。
- `NoWrap`・`NoClip`・`Trimming=None` を指定し、幅を超える文字は切らずに描画する（Excelと同じ見え方）。既定の Trimming=Character だと末尾の文字が消える（例：「得Rank=」の「=」）。
- `left` と指定なしは従来どおり `x0+3` に描画する。

### 3.2 整列定義の補完（config\label_layout_full.json）
- 原典ブック（`@(自動)企画室 船舶値付用紙出力-DebugTsuka.xlsm`）の model シートの横位置設定のうち、JSONに無かった **33セルを追加**した（551 → 584セル）。既存のセル定義は変更していない。
- 追加セル：L4, L5, L6, A10, F10, O10, AW10, BO10, AW11, A12, I12, N12, U12, V12, Z12, AS12, AY12, BC12, BJ12, O13, V13, AI13, AS13, BC13, BJ13, A14, Y14, AI14, BC14, BJ14, A15, A16, BM16
- 変更記録として `_layoutfix_20261013` キーを追加（スクリプトは参照しない）。
- 他の6つのJSONは変更なし。

### 3.3 縮小率・列幅・行高・配置（スクリプト、1ページに収まる手配のみ）
2026-10-02〜10-13 の原典VBAのDocuWorks出力（346ページ）を実測し、次の規則を確認して再現した。

| 明細数 | Excel縮小率 |
|---|---:|
| 1〜7 | 71% |
| 8 | 65% |
| 9 | 58% |
| 10 | 54% |

- 列幅 = round(134 × 縮小率)、行高 = round(122.7 × 縮小率)（いずれも600dpiのデバイス画素）
- 用紙全幅の左右中央に配置。上端は従来どおり（約0.5cm）。
- 横と縦で別の倍率を使う（`ScaleTransform(scaleX, scaleY)`）。
- **11明細以上（複数ページ・固定倍率）は過去データに該当が無く未検証のため、従来処理のまま変更していない。**

### 3.4 円記号（スクリプト）
- 請求合計（V13）・原価合計（BJ13）・製造原価合計（BJ12）の書式を `￥`（U+FFE5）から `\`（U+005C）へ変更。原典VBAのログでも全て U+005C。游ゴシックで半角「¥」として印字される。
- **（第2版で追加）** 一式金額（AV5）の3つの書式（請求・経由・受注）も `￥` から `\` へ変更。第1版では「VBA実例が無い」と誤認して未変更だったが、過去の証跡にVBA実例が3件あり、いずれも U+005C だった。2026-10-09分（一式金額 E269785080 を含む）を実印刷し、AV5 がVBAと完全一致、同日の印字値の差が22件→0件になったことを確認。
