# CSV参照元の調査と修正仕様

2026-10-06。対象 E26A043550。

## 厳密に確認できた参照元

当日CSVの236行目（ヘッダーを1行目として数える）の実データは次のとおり。

| 列番号 | CSV項目名 | 実値 | 帳票での使用 |
|---|---|---|---|
| 5 | 得意先番号 | 1915 | F4 得意先コード |
| 111 | 受注先番号 | 1915 | F5 受注先コード |
| 112 | 受注先名 | 船舶機械部 返品・支給･社内加工 | 受注先名称 |
| 65 | 販売部門 | B1915（末尾空白あり） | B1 部署名の参照元 |
| 262 | 所属部署コード | B1915（末尾空白あり） | VBAの抽出・部署判定で参照 |

setting_mapping.jsonのF4はsource_field_id=5、F5は111。部署コード列65/262から4桁を抽出してF4/F5へ入れる分岐ではない。両帳票は「得意先番号・受注先番号の欄に入っている1915」を出力している。

受注先名称が内部部署向けであり、部署欄のB1915とも対応しているため、得意先／受注先欄に部署兼用のコードを設定した社内取引と整合する。ただし、マスターのコード定義・兼用規則まではCSVと帳票処理だけでは確定できない。「正式な部署コードの種別」と「今回どのCSV列を印字したか」は区別する。

## 原典VBAとPSの違い

原典VBA Process.MakeData（保存済みProcess.bas 1337～1349行付近）は得意先番号・受注先番号・納入先番号を文字列扱いにし、長さ6なら00、7なら0を付ける。4桁には追加しない。4桁の1915はそのまま印字される。

PSはF4/F5/F6の数字について8桁未満を一律PadLeft(8)していた。「原典は常に8桁」というPSコメントの前提が誤っており、今回の不一致原因はこの補完条件だった。修正版は数字6桁・7桁だけ8桁へ補い、4桁・5桁・8桁・特殊10桁は保持する。特定の1915や手配書番号をハードコードしていない。

## 日付表現の補正

E26A040700の当日CSV212・213行目の124列（発注者1）は08-4010。VBA FINALログおよび実印刷は8/1/4010。PS従来は元文字列を保持していた。

検証版の既存F8／ID124限定関数へ、ASCIIの月－4桁年形式を有効な年月ならその月1日のM/d/yyyyへ変換する分岐を追加した。年1900未満、不正月、末尾文字、全角入力は保持する。既存の日本語月日補正は維持する。Excelの全CSV型推論を再現したとはしておらず、他の日付書式は未対象。月－年形式全般とExcelとの一致は今回の08-4010以外で追加検証が必要。

## 検証結果と適用状態

Windows PowerShell5.1の単体15ケースPASS。全44注文・113明細の印刷なしプレビューを実行し、2619キーの増減なし。変わった値はF8の1件とF4/F5の2件だけで、3件とも今回のVBA実測値に一致。他2616値は不変。

修正版はこのフォルダー内へ分離。before.ps1に元版を保持し、manifest.jsonに両版と入力のSHA256を記録。原典VBA、保存済み検証ブック、日次PS、Windowsタスクは変更していない。修正版の実印刷試験は未実施であり、完成版や日次採用済みとはしない。
