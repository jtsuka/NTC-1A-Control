# RK10LOG-REMOVE PowerShell化 詳細設計書 (REV1)

対象スクリプト: `Remove-RK10Log.ps1`
元シナリオ: `RK10LOG-REMOVE`（RK-10、全50ステップ）

---

## 1. 目的

RK-10 のシナリオログ／ライセンスログを一括削除するシナリオが遅いため、同一の削除仕様のまま PowerShell に置き換え、実行時間を短縮する。

## 2. 元シナリオの解析結果

### 2.1 処理概要

| ステップ | 内容 |
|---|---|
| 1, 47〜50 | try / catch。エラー時は呼び出し履歴を実行ログに出し、シナリオ終了 |
| 3 | TODAY = 現在日時 |
| 4〜9 | 引数1(Arg1)を取得。`Arg1 = "1"` なら `Log_OR_License = True`（シナリオログ）、それ以外は False（ライセンスログ） |
| 10〜18 | 対象フォルダーと保持日数を決定（下表） |
| 19 | DEL_DATE = DAY_FOR_DAY の時刻を 0:00 にしたもの（= 基準日時） |
| 20 | 対象フォルダー直下のフォルダー一覧取得（**以降で未使用**） |
| 22〜34 | 【シナリオログ】LOG 直下の**フォルダー**を表で取得 → 1行ずつ「作成日時 < DEL_DATE」ならフォルダーごと削除 |
| 35〜44 | 【ライセンスログ】LOG\License 直下の**ファイル**を表で取得 → 1行ずつ「作成日時 < DEL_DATE」ならファイル削除 |

| | シナリオログ (Arg1=1) | ライセンスログ (Arg1≠1) |
|---|---|---|
| 対象パス | `\\192.168.0.35\disk\企画室\RPA\LOG` | `\\192.168.0.35\disk\企画室\RPA\LOG\License` |
| 保持日数 | 3日 | 7日 |
| 削除単位 | 直下のフォルダー（中身ごと） | 直下のファイル |
| 判定列 | 作成日時（※更新日時ではない） | 作成日時 |
| 判定 | 作成日時 < (今日 − N日) の 0:00 | 同左 |

その他の読み取り事項:
- 「更新日時 0日以上前」のフィルターは全件対象の意味（実質フィルターなし）。
- 各行ごとにデバッグ用の実行ログ出力あり（ステップ28, 33, 39, 44）。
- ステップ20の `PK10_LOG_LIST` は結果をどこでも使っていない。
- ステップ45, 46 は空ブロック（何もしない）。
- 原シナリオでは**途中の1件でエラーが出ると catch に落ちて全体が終了**する。

### 2.2 遅い原因（推測）

実測はしていないので、あくまで推測です。

1. 対象が1件ごとに RK-10 のアクション4〜6個（値取得×2、ログ出力、条件分岐）を実行しており、**削除しない行にも同じコストがかかる**。
2. 行ごとの実行ログ出力が、件数に比例して増える。
3. NAS（UNC）上で、フォルダー内のファイルを RK-10 の削除アクションで処理している。

PowerShell 版では、.NET の `DirectoryInfo.EnumerateDirectories/EnumerateFiles` で一覧と作成日時を一括で取得し、削除対象だけを処理する。ログも削除した項目と結果サマリーのみにする。NAS 上の削除そのものの時間は PowerShell でも残るため、削減効果は **DryRun と本実行の所要時間**で確認する。

## 3. 新スクリプトの仕様

### 3.1 呼び出し

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<配置パス>\Remove-RK10Log.ps1" 1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<配置パス>\Remove-RK10Log.ps1" 2
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<配置パス>\Remove-RK10Log.ps1" 1 -DryRun
```

### 3.2 パラメーター

| 名前 | 既定値 | 説明 |
|---|---|---|
| LogType (位置0) | なし(必須相当) | `1`=シナリオログ、`0`/`2`=ライセンスログ。それ以外・省略は終了コード2で何も削除しない |
| ScenarioLogDir | `\\192.168.0.35\disk\企画室\RPA\LOG` | |
| LicenseLogDir | `\\192.168.0.35\disk\企画室\RPA\LOG\License` | |
| ScenarioRetentionDays | 3 | |
| LicenseRetentionDays | 7 | |
| ExcludeFolderName | `License` | シナリオログ走査で除外するフォルダー名（4.1参照） |
| LogFile | `<スクリプトのフォルダー>\Logs\RK10LOG-REMOVE_yyyyMMdd.log` | 自身のログ（UTF-8 BOM付き） |
| ScriptLogRetentionDays | 30 | 自身のログの保管日数 |
| DryRun | off | 削除せず対象一覧のみ出力 |

### 3.3 処理フロー

```
開始 → ログ初期化
  → LogType 判定（不正なら exit 2）
  → 基準日時 = (今日 − 保持日数) の 0:00
  ├ LogType=1: LOG 直下のフォルダーを列挙
  │    作成日時 < 基準日時 かつ 除外名でない かつ リンクでない
  │    → 対象リスト確定 → 1件ずつ DirectoryInfo.Delete(recursive)
  └ LogType=0/2: License 直下のファイルを列挙
       作成日時 < 基準日時 → 対象リスト確定 → 読み取り専用を解除して Delete
  → サマリー出力（走査/対象/削除/失敗/除外/スキップ/所要秒）→ 終了コード
```

- 列挙中の削除を避けるため、先に対象リストを確定してから削除する。
- 1件の削除に失敗しても他の項目は続行し、失敗数を数えて最後に終了コード1で通知する（原シナリオは1件失敗で全体停止）。

### 3.4 終了コード

| コード | 意味 |
|---|---|
| 0 | 正常（対象0件を含む） |
| 1 | 一部の項目で削除失敗 |
| 2 | 引数不正（削除なし） |
| 3 | 致命的エラー（対象フォルダーにアクセスできない等） |

### 3.5 ログ

標準出力とログファイルの両方に `yyyy-MM-dd HH:mm:ss [LEVEL] メッセージ` 形式で出力する。出力するのは開始、基準日時、削除した項目、失敗・警告、終了サマリーのみ。削除しない項目は出力しない。

## 4. 原シナリオとの差異・要確認事項

### 4.1 【要判断】License フォルダーの扱い

ライセンスログ用フォルダー（`LOG\License`）は、シナリオログの走査対象である `LOG` の**直下**にあります。原シナリオのままだと、`License` フォルダー自体の作成日時が3日より古い場合、シナリオログ削除（Arg1=1）で `License` が中身ごと削除される可能性があります。

新スクリプトでは `ExcludeFolderName` で `License` を既定で除外しています。原シナリオと同じ挙動にしたい場合は `-ExcludeFolderName @()` を指定してください（通常は除外のままで問題ないはずですが、実運用で `License` が消えていないかご確認ください）。

### 4.2 引数の扱い（厳格化）

原シナリオは「`1` 以外はすべてライセンスログ」でした。新版は `1`、`0`、`2` のみ受け付け、それ以外は何も削除せず終了コード2を返します。呼び出し側のシナリオが実際にどの値を渡しているか、確認してください。`1` と `2` 以外の値を渡している場合は、`switch` の許容値を追加する必要があります。

### 4.3 エラー時の挙動

原シナリオは1件のエラーで全体終了。新版は続行し、最後に終了コード1で通知します。

### 4.4 ログ出力先

原シナリオは RK-10 の実行ログに行ごとに出力していました。新版はログファイルと標準出力にのみ出力し、行ごとのデバッグ出力はしません。

### 4.5 未解決の確認事項

- 判定が「作成日時」のため、作成が古く、中身が最近更新されているフォルダーも削除されます。これは**原シナリオと同じ仕様**です。更新日時基準に変えるかは別途判断してください。
- 読み取り専用ファイルを含むフォルダーを `Delete(recursive)` するとき、.NET Framework では失敗する場合があります。その場合は失敗ログに残るので、DryRun と本実行で確認してください。
- 実行アカウントに NAS 上の削除権限があること（RK-10 実行ユーザーと同一かどうか）。

## 5. 文字コードと実行環境

- 日本語パスを含むため、`.ps1` は **UTF-8 BOM 付き**で保存する（Windows PowerShell 5.1 の文字化け対策）。
- Windows PowerShell 5.1 以上を想定。外部モジュールは使いません。

## 6. テスト計画

| # | 内容 | 期待結果 |
|---|---|---|
| T1 | `1 -DryRun` | 3日より前に作成されたフォルダーのみ列挙、`License` は除外ログ、削除なし |
| T2 | `2 -DryRun` | 7日より前に作成されたファイルのみ列挙、削除なし |
| T3 | テスト用フォルダー（ScenarioLogDir 差し替え）で `1` を本実行 | 対象のみ削除、新しいフォルダーは残る、終了コード0 |
| T4 | テスト用フォルダーで `2` を本実行 | 対象ファイルのみ削除、サブフォルダーは残る |
| T5 | 境界値: 基準日時ちょうど前後の作成日時 | 基準日時未満のみ削除 |
| T6 | 引数なし / `9` / `abc` | 終了コード2、削除なし |
| T7 | 存在しない対象パス | 終了コード3 |
| T8 | ロック中ファイルを含む状態 | 該当のみ失敗ログ、他は削除、終了コード1 |
| T9 | 件数が多い状態で所要時間を原シナリオと比較 | 短縮を確認 |
| T10 | RK-10 から呼び出し（引数1/2、終了コードの受け取り） | 想定どおり動作 |

テストは必ず `-ScenarioLogDir` / `-LicenseLogDir` を**テスト用フォルダー**に差し替えて、DryRun → 本実行の順で行います。

## 7. レビュー依頼ポイント（チャッピー向け）

1. 原シナリオとの削除判定（作成日時、基準日時の0:00丸め、保持日数）が一致しているか。
2. `License` 除外（4.1）と引数厳格化（4.2）の妥当性。
3. 誤削除のリスク（パス誤り、UNC、リンク、列挙中削除）に対する防御は十分か。
4. PowerShell 5.1 での文字コード、`Delete($true)` の挙動、終了コードの扱い。
5. 大量ファイルでの性能（並列化の要否）。
