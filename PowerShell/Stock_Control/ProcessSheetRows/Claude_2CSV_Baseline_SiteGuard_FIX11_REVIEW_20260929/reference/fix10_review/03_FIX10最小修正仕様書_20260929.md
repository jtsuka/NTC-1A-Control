# FIX10 最小修正仕様書 — Baseline Gate / Phase3運用可視化

対象: ProcessSheetRows r15.10 REV5.1 2CSV
日付: 2026-09-29
状態: REVIEW CANDIDATE / 未本番投入

## 1. 目的
2CSVのBaseline未初期化状態で、Phase1 stagingだけが本番生成され、人が移動先を入力できる一方、Phase3は永久にSKIPする中間状態を防止する。

同時に、未試験のBaseline History新規作成経路へFIX9のCOM型明示ルールを適用する。

## 2. 非目的
- Phase3業務ロジックの変更
- CandidateKey仕様変更
- Main/Sub境界変更
- Baseline自動初期化
- 既存管理CodeのSourceType自動推測
- 1CSV仕様変更
- Historyレイアウト全面変更

## 3. 変更仕様

### FIX10-01 Baseline未初期化2CSVのPhase1 Update Gate
条件:
- 新規コード機能 Enabled
- FeatureError=False
- DatasetCount=2
- HistoryStateが未作成またはBaselineInitialized=False

動作:
- Audit候補検出/CSV出力は継続
- 通常在庫ロジックは継続
- Phase1 stagingへの新規書込はSKIP
- Phase3もSKIP
- Baseline Initializeは明示 `-InitializeNewProductBaseline` のみ

### FIX10-02 Pending manual instruction可視化
Baseline未初期化時でも既存stagingをREAD ONLYで走査し、
商品コードあり＋移動先入力済み行数を
`Phase3PendingInstructions=<count>`
としてWARNログに出す。

これにより「人入力済みなのにBaseline Gateで止まっている」ことをログから即判別可能にする。

### FIX10-03 Phase3 SKIPログの正確化
現行はBaseline理由でFeatureEnabledをfalseにした後、
`新規商品コード機能が無効/ERROR` とも出力するため、
`Enabled=True FeatureError=False` と文言が矛盾する。

FIX10ではSkipReasonを保持し、Baseline未初期化ならその理由だけを明示する。

### FIX10-04 Baseline switchの開始ログ
`InitializeNewProductBaseline=True/False`
を実行開始ログへ追加。

### FIX10-05 History新規作成COM安全化
`Write-NewProductHistoryRows` で
- ヘッダー配列要素 → `[string]`
- CandidateKey/Code/SourceType/SourceLabel/DestinationSheet/State/Note → `[string]`
をCOM `Value2` 直前で明示。

ヘッダーはFIX9のstaging対策と同様、
1セルずつ `NumberFormat="@"` → `[string]Value2` とする。

## 4. 既存仕様を維持する項目
- Baseline InitializeとPhase3 Moveは同一runで混在させない
- Baseline Initialize時はHistoryへBaselineManagedを登録
- Phase3成功時だけstaging削除
- 2CSV Phase3成功時だけHistoryへRegistered追加
- MaxNewProductMoves=200
- Phase3途中エラーはSave前停止
- 1CSV既存挙動
- 2CSV CandidateKey = Code|SourceType

## 5. 今回あえて修正しない設計差分
REV5設計書はBaseline状態をK/Lセル＋SiteNameで定義しているが、
現行実装はHistoryシート J1=`BASELINE_INITIALIZED` を判定している。

これは現在の未発火の直接原因ではない。
FIX10へ同時に入れると変更範囲が広がるため、
Claudeに「今直すべきCriticalか／別改修へ分離すべきか」を判定依頼する。
