# App292 U1 テスト準備手順
## 目的

U1では、既存の `Batch` レコードについてCSV側の納期だけが変わった場合に、

1. 既存レコードとして認識される
2. `UPDATE_RECALC` に分類される
3. 基幹納期 `日付_1` が新納期へ更新候補になる
4. `K加工着手日 / K完成検査日` が再計算される
5. `K日程種別=Batch` を維持する
6. revision / before / after / changeHash がManifest JSONへ出る
7. Execute直前ガード後にPUTし、再GET検証できる

ことをApp292で確認する。

## 使用レコード

- App: 292
- PO: `2609249755`
- 現行手配日: `2026-09-15`
- 現行納期: `2026-11-02`
- U1テスト新納期: `2026-11-06`

このPOはApp292のテスト用レコードとして使用する。

```text
RESULT           : BASELINE PLAN PASS
```

## Step 2: App292をBatch基準状態へ整える

Step 1が正常な場合だけ実施。

```powershell
.\Prepare-App292-U1_BatchBaseline_v0.1.ps1 `
  -Execute `
  -ConfirmExecute "APP292-U1-BASELINE"
```

App292のこのレコードは過去のmaster lifecycle試験でVendor/Staffがテスト値になっているため、
U1を「納期だけの差分」に限定する目的で、次の基準値へ戻す。

- `VENDOR_TEXT = ㈱吉川鉄工所`
- `VENDOR_DD = ㈱吉川鉄工所`
- `STAFF_TEXT = 木村　和也`
- `STAFF_DD = 木村　和也`
- `K加工着手日 = 2026-10-26`
- `K完成検査日 = 2026-10-30`
- `K日程種別 = Batch`
- `K暫定設定 = ON`
- `K計算根拠 = Company`

発注番号、ODERNO、手配日、納期は変更しない。

---

## Step 3: U1用1行CSVを作成

```powershell
.\New-App292-U1_TestCsv_v0.1.ps1
```

出力:

```text
C:\HPDB\App292_U1_2609249755_DueChanged_20260916.csv
```

このCSVは本番整形済みCSVからPO `2609249755` を1行だけ抽出し、**納期だけ**を

```text
2026-11-02
↓
2026-11-06
```

へ変更する。

スクリプト自身が「変更フィールドが納期1項目だけ」であることを検証し、それ以外が変わった場合は停止する。

---

## Step 4: 生成CSVを目視確認

```powershell
Import-Csv "C:\HPDB\App292_U1_2609249755_DueChanged_20260916.csv" |
  Select-Object 発注番号,ODERNO,指示先名,手配担当者名,手配日,納期 |
  Format-List
```

期待:

```text
発注番号       : 2609249755
ODERNO         : T268059010
指示先名       : ㈱吉川鉄工所
手配担当者名   : 木村　和也

```

Step 2でApp292側のVendor/StaffもCSV正本値へ揃えているため、
Step 4のCSVとの差分は原則として `納期` のみになる。


- `K日程種別_候補 = Batch`
